## 이게 뭔가

회장님이 관장하는 여러 회사(지금은 `company1/`의 "작업실 컴퍼니"[→나다컴퍼니1] +
`pixel-ai-office`의 "새사업 스튜디오"[→프로토타입으로 재정의])를 **한 화면에서 오가며
드릴다운**하는 지주사 콘솔.

`pixel-ai-office`(원래 다운로드받은 픽셀아트 템플릿을 커스터마이즈한 것)를 회장님이 써보시고
"다른 사람이 만든 걸 쓰려니 내 입맛에 안 맞는다"고 판단, **완전히 새로 설계·구현**한 것이
이 프로젝트다. `pixel-ai-office`는 지우지 않고 그대로 두었고(라이브 유지, 나다그룹 HQ에서
"프로토타입" 항목으로 거기로 링크됨), 자리잡으면 나중에 정리하기로 했다.

## 확정된 디자인 결정 (회장님이 직접 컨펌, 순서대로)

작업 과정에서 Claude Artifact로 여러 후보를 목업해서 보여드리고 그중 확정한 것들:

1. **비주얼 방향**: "오퍼레이션 콘솔" — 다크 테마, 좌측 회사 nav + KPI 스트립 + 오피스 플로어.
   (검토했던 다른 3안: 아이소메트릭 오피스 / 조직 그래프 / 보드형 브리핑 — 전부 기각)
2. **인물 렌더링**: 픽셀 계열 확정. (3D 미니피규어 / 심플 실루엣 / 탑다운 블루프린트 /
   레오나르도AI 실제 생성본까지 비교했으나 픽셀 유지. 원본 픽셀오피스보다 팔레트를 다크
   콘솔 톤으로 눌러서 "게임"보다 "터미널"에 가깝게.)
3. **캐릭터는 고정 인원 아님** — 레이어 3장(베이스·상의·헤어) + 사원증 1종을 직원 ID로 시드
   고정한 결정론적 조합으로 생성. AI 호출 없이 무한 다양성, 같은 사람은 항상 같은 모습.
   구현: `src/characters/traits.ts`(팔레트+해시), `CharacterSprite.tsx`(합성 렌더),
   `CharacterDefs.tsx`(SVG 심볼 정의, 페이지에 1번만 마운트).
4. **사원증 규칙**: 대표(사장)만 미착용, **팀장 포함 나머지 전원 착용**. (처음엔 "임원
   전체 미착용"으로 만들었다가 회장님이 "팀장은 달아야 한다, 임원급 C레벨만 빼라"고 정정 —
   지금 구조에선 사실상 "대표 1인만 예외"로 단순화됨. 상의의 넥타이 모양이 사원증이랑
   헷갈린다는 피드백 받고 제거함.)
5. **팀장/팀원 방 + 회의실** — 원본 픽셀오피스의 룸/미팅 엔진 개념을 차용. 대표실 + 부서별
   방(팀장+팀원) + 회의실.
6. **이름표는 방이 아니라 사람(캐릭터)에 부착** — 이동해도 같이 따라감.
7. **네이밍 정책**: 회장님은 **대표(사장) 이름만** 지어주신다. 나머지는 전부 역할명으로
   표시(예: "전략팀장"). 지금 `company1/README.md`엔 혜안·재현·윤슬이라는 실명이 있지만,
   **이 대시보드에서는 의도적으로 역할명만 노출**하기로 확정했다 — company1/의 실제 헌장을
   고친 게 아니라 이 화면의 표시 정책만 그런 것.
8. **승인 대기 vs 지시 접수함 분리**:
   - 승인 대기 = 예/아니오형 단순 상태 변경 → 대시보드에서 즉시 처리
   - 지시 접수함 = 판단이 필요한 요청 → 그 자리에서 답하지 않고 "접수"만, Claude 세션이
     비동기로 처리 (대시보드 자체가 LLM 채팅창이 되지 않도록 하는 설계 원칙)
9. **"10개 관계사 사장 소집 회의" 같은 멀티 에이전트 상담**은 라이브 멀티턴 채팅 UI가 아니라,
   Workflow 툴로 사장 여러 명을 병렬 서브에이전트로 독립 검토시키고 종합하는 방식으로
   처리하기로 함 — `company1/README.md`의 기존 "독립 검토 → 사장 종합" 원칙과 그대로 맞물림.

## 지금 구현 상태 (Phase 1 — 완료)

- `Vite + React + TS`, `pixel-ai-office`와 동일 빌드 패턴(`base: "./"`, `outDir: "play"`).
  라이브 예정 주소: `https://tossneon.github.io/holdco/play/`
- 파일 구조:
  - `src/characters/` — 트레잇 팔레트·해시(`traits.ts`), SVG 심볼 정의(`CharacterDefs.tsx`),
    합성 렌더 컴포넌트(`CharacterSprite.tsx`)
  - `src/data/holdco.config.ts` — 회사·방·직원·사업라인·승인·지시 데이터.
    `registry.js`/`ai-office/status.js`와 같은 **스냅샷 패턴**(실시간 연동 아님, 의미 있는
    변화가 있을 때마다 이 파일을 갱신)
  - `src/App.tsx` — 전체 UI 로직, `src/app.css` — 스타일
- 회사 2개 등록:
  - `hq`("작업실 컴퍼니") — `mode: "op"`, 이 콘솔에서 직접 운영 화면(방·회의실·사업라인·
    승인·지시함)을 보여줌. `company1/candidates.md`의 실제 A1~A5 사업 라인 현황을 반영함
  - `newventure`("새사업 스튜디오") — `mode: "external"`, `pixel-ai-office` 라이브 오피스로
    링크만 나감(중복 구현 안 함)
- 승인 대기/지시 접수함은 **로컬 React state만** — 새로고침하면 초기값으로 리셋됨.
  의도된 Phase 1 한계(아래 Phase 2 참고).
- 데스크톱/모바일 반응형을 Playwright 스크린샷으로 확인 완료.

## 미완료 — Phase 2 (다음에 할 일)

**목표**: 승인/지시 상태를 실제로 영속화하고, "지시 접수함"에 넣은 요청이 진짜 Claude
세션까지 도달해서 처리되게 만들기.

1. **백엔드**: Cloudflare Worker + KV (`pixel-ai-office/worker` 패턴 재사용 예정). 지금은
   `App.tsx`가 로컬 state로만 승인/지시를 다루는데, 이걸 그 Worker에 대한 fetch 호출로
   바꿔야 한다.
2. **지시 접수함 → Claude 세션 연결 방식**: Worker가 직접 Claude 세션을 깨우는 공개 API는
   없다(MCP 트리거 툴은 에이전트 세션 쪽 권한이라 Worker가 못 씀). 그래서 **예약 트리거
   (Routine, cron)**로 주기적으로(예: 매시간) Claude 세션이 깨어나서 Worker의 큐를 읽고
   "접수됨" 상태인 지시를 처리 → 결과를 다시 Worker에 써넣는 방식으로 설계하기로 확정.
3. **막힌 지점**: Worker 배포에 Cloudflare API 토큰이 필요한데, `pixel-ai-office/worker`도
   같은 이유로 아직 미배포 상태다(회장님께 토큰 요청했다가 이 프로젝트 작업으로 넘어오면서
   흐지부지됨). **두 Worker(pixel-ai-office + holdco)를 한 번에 같이 배포하는 게 효율적**
   이라고 제안해둔 상태 — 회장님 답변/토큰 재발급 대기 중.
   토큰 발급 경로: https://dash.cloudflare.com/profile/api-tokens → "Edit Cloudflare
   Workers" 템플릿 → Create Token.
