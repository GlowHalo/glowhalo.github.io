# GlowHalo 3 — 관계사 헌장 (자산운용)

GlowHalo Group 산하 세 번째 관계사. 대표: **은성** (2026-08-09 선임). GlowHalo 1(`niche-templates/`, 정연)·GlowHalo 2(`niche-api/`, 하윤)가 신사업 탐색 트랙인 것과 달리, GlowHalo 3는 **완전히 다른 도메인 — 자산운용**을 맡는다: 코인 또는 주식 중 하나를 골라 초기자본 30만원으로 시작해 수익을 최대화하는 것이 미션.

공유 원칙(회장 리소스 제약, 공개저장소 주의, 조직 확장은 사후 기록·사전 승인 불필요, 신규 역할은 실명 없이 역할명만)은 루트 [`CLAUDE.md`](../CLAUDE.md)와 [`niche-templates/README.md`](../niche-templates/README.md)를 그대로 따른다. 이 문서는 GlowHalo 3만의 차이점만 적는다.

## ✅ 실거래 권한 — 게이트 해제됨, Phase 1 가동 중

**현재 실거래가 승인된 상태다.** 은성은 원금 30만원 한도 안에서 **건별 승인 없이 자율로 매수/매도를 집행한다.** 자동화된 무인 실행(예약 루틴)도 이 위임에 포함된다 — 아래 해제 근거가 그 권한의 출처다.

### 해제 근거 (2026-08-10, 회장 확정)

게이트의 두 조건이 모두 충족되어 해제됐다:

1. **계좌**: 회장이 업비트 실계좌 개설·KYC 완료, API 키(자산조회+주문조회+주문하기, **출금 권한 없음**) 발급·금고 등록·인증 테스트 성공.
2. **권한 범위**: 회장이 **"30만원 한도 내 완전자율"**로 확정 — "최초 계획대로 30만원 안에서 알아서 운용. 손실 나면 그 안에서 재투자 여부도 은성이 알아서 결정. **30만원을 잃으면 끝 — 추가 입금은 없다.**"

2026-08-15에 **주문 경로 실검증까지 완료**됐다(KRW-BTC 5,500원 왕복 실체결, 수수료 5원). 매수·매도 양방향이 실제로 작동함이 확인된 상태다.

운용 규칙은 [`MODE.md`](MODE.md)가 정본: 리스크 헌법(포지션 손절 -3%, 일 -3%/주 -7% 한도, 서킷브레이커 -15% 시 전면 중단·회장 보고)이 `execution/live_trade.py`에 코드로 내장돼 있어 한도를 넘는 주문은 만들어질 수 없다. 이는 회장 위임 범위보다 훨씬 보수적이다. 원금 소진(-100%)은 회장이 명시한 회사 종료 조건이므로, 그 훨씬 전에 시스템이 멈추도록 설계돼 있다.

### 해제 이전의 게이트 (2026-08-09~08-10, 이력)

아래는 **이미 종료된 제약**이다 — 지금은 적용되지 않으며, 판단 근거로 삼지 말 것. 당시 원칙은 이랬다: 실제 시장 손실은 되돌릴 수 없으므로(CLAUDE.md 자율성 원칙 1번) 조사·백테스트·페이퍼는 자율로 하되, 실제 매수/매도는 ① 회장의 계좌 개설·KYC와 ② 권한 범위 확정 전까지 하지 않는다. 두 조건이 위와 같이 충족되면서 이 제약은 해제됐다. (`niche-templates/README.md`의 같은 절도 이 해제를 반영한다.)

## 예산 원칙

- **초기자본 30만원(KRW) 1회** — GlowHalo 1/2의 "아이디어 1건당 30만원" 반복 지출 개념과 다르다. 이 30만원 자체가 GlowHalo 3의 유일한 운용 원금이고, 뚜렷한 성과가 확인되면 회장 승인을 거쳐 증액한다.
- 페이퍼 트레이딩(모의투자)·백테스트는 무자본이므로 자본 배분과 무관하게 계속 병행한다 — 현재 v2(실거래 채택)와 v3의 A/B 전진 검증 중.

## 조직 구조

- 대표(CEO) **은성** — 2026-08-09 선임. 1인 체제로 시작. 리서치/리스크관리 등 실행 부담이 커지면 회장 승인 없이 자율로 역할을 신설하고 여기 기록한다(신규 역할은 실명 없이 역할명만 — GlowHalo 1 호칭 정책과 동일).

## 기록

- `candidates.md` — 자산군 비교(코인 vs 국내주식 vs 해외주식)와 최종 선택, 초기 전략의 최신 확정 상태 (Living Doc, GlowHalo 1/2와 동일한 패턴).
- `board/` — 라운드별 조사/회의 기록 (필요해지면 추가).
- `execution/` — 페이퍼 트레이딩 로그, 전략 백테스트 결과, **실거래 집행 기록**(`live/`). 실거래 상태 정본은 금고(`company3_live_state`)이고 `sync_state.py`가 저장소로 내린다 — 이유는 [`HANDOFF.md`](HANDOFF.md)의 인프라 구조 절 참고.
- [`재무.md`](재무.md) — 초기 출자금·실현손익 기록 (개인사업자 기준, 원칙은 [`hq/재무.md`](../hq/재무.md)). 실거래 청산 시 즉시 갱신할 것.

## 공개 저장소 주의 (자산운용 특화)

- 거래소/증권사 로그인 정보, API 키, 계좌번호, 실제 보유 자산·손익 내역은 **절대 이 폴더(공개 저장소)에 적지 않는다** — `cloudflare-api-vault/`(금고)와 gitignore 대상 `data/`류 폴더에만 둔다. 자세한 사용법은 [`.claude/rules/cloudflare-vault.md`](../.claude/rules/cloudflare-vault.md).
- 전략 로직·페이퍼 트레이딩 결과처럼 실제 자산 규모나 신원을 특정하지 않는 정보는 공개해도 무방하다.
