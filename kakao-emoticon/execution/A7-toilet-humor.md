## 다른 시리즈와의 차이 — 제작 방식 자체가 다름

- A3(일잘봇)·A4(새침냥이)·A6(몽글곰)은 전부 **Leonardo AI**로 생성한 래스터(JPG/PNG) 아트워크를 후처리한 것.
- A7은 **외부 이미지 생성 AI를 전혀 쓰지 않는다.** 몸통 실루엣 하나를 SVG 경로로 고정해두고, 눈썹·눈·입·팔·아이콘·대사를 파이썬 딕셔너리 프리셋으로 조합해 32종을 코드로 직접 조립한 뒤 로컬 Chromium으로 PNG 렌더링한다. Leonardo의 "고정 시드+표정 교체" 원칙을 벡터로 재현한 것.
- 장점: Leonardo API 크레딧 0원, 파일 용량 매우 가벼움(17~22KB, 150KB 한도의 1/7 수준), 캐릭터 일관성 100%(좌표 재사용이라 개체차 자체가 없음).
- 단점: 유기적인 붓터치·그라데이션이 없어 스타일이 평면적. 팔 포즈 등 디테일을 늘리려면 사람이 좌표를 직접 조정해야 해서(AI처럼 프롬프트만 바꿔서 다양성이 안 나옴) 표현 폭에 품이 더 든다.

## 제작 방식 상세

- `products/toilet-lineart-a7/scripts/generate_svg.py`: 몸통 고정 경로(BODY) + 팔 11종 프리셋(ARMS) + 눈썹 4종 + 눈 5종 + 입 7종 + 아이콘 9종 + 대사(Jua 폰트, 흰 테두리로 가독성 확보, 7자 넘고 공백 있으면 자동 2줄) 조합.
- 한글 폰트가 이 실행환경에 기본 설치돼 있지 않아(Unifont만 있어 한글이 깨져 보임) Google Fonts "Jua"(jsdelivr CDN 경유)를 받아 `~/.fonts`에 설치해서 사용 — **세션이 바뀌면 이 폰트도 다시 설치해야 함**(재설치 방법: `curl -sSL -o ~/.fonts/Jua-Regular.ttf "https://cdn.jsdelivr.net/gh/google/fonts@main/ofl/jua/Jua-Regular.ttf" && fc-cache -f`).
- `products/toilet-lineart-a7/scripts/render_png.mjs`: 로컬 Chromium(`/opt/pw-browsers/chromium-1194`)으로 SVG→PNG 렌더링. Cloudflare Browser Rendering이나 세션 프록시를 전혀 안 거침(로컬 파일 렌더링이라 네트워크 자체가 불필요) — 카카오 로그인 자동화와는 완전히 무관한 별도 경로.
## 2차 다듬기 (2026-08-15, 같은 날 후속 — "네 판단에 최선일 때까지 다듬어" 지시)

실제 제출 전 스스로 품질을 다시 점검하다가 **치명적인 결함을 발견해서 고쳤다**: 몸통·팔을 `fill:none`(테두리만, 속은 완전 투명)으로 그리고 있었다. 흰 배경 미리보기에서는 멀쩡해 보였지만, **카카오톡 다크모드 채팅창(어두운 배경)에 올리면 검정 테두리가 어두운 배경과 거의 구분이 안 돼 캐릭터가 사실상 안 보이는 수준**이었다(실제로 어두운 배경에 합성해서 확인함). 실물 스티커라면 절반의 사용자에게 무용지물이 될 뻔한 문제.

- **수정**: 몸통·팔을 흰색으로 채우고 검정 테두리를 두르는 방식으로 변경(일반적인 카카오 라인아트 스티커 관례와 동일). 은은한 드롭섀도우도 추가해 스티커 특유의 "붙어있는" 느낌을 살림.
- **부수 효과로 5번(물 내려) 팔 포즈 문제도 해결**: 회전시켜 재사용하는 방식으로 고쳐보려 했으나 팔이 몸통 반대편으로 넘어가 더 이상해지는 걸 확인 → 무리하게 새 포즈를 밀어붙이지 않고 이미 검증된 `shrug`(으쓱) 포즈로 교체. 텍스트 대사가 이미 의미를 전달하므로 포즈가 완벽히 "가리키는" 동작이 아니어도 무방하다고 판단.
