## 발견된 문제 — 이미지가 장면 중간에 바뀜 (1.아 제외 9회차)

`1.아` 만 이미지 배치가 깨끗했다. 대본 블록(빈 줄로 나뉜 덩어리) 경계와 이미지 경계가 정확히 일치:

```
A A | B B B | C C | D D D | E E | F F F ...   (14 블록 = 14 이미지)
```

나머지 9회차는 경계가 어긋났다. 예) `7.우`:

```
... E E F ...   "우유, 우유," 두 줄은 E, 그런데 "우유에도 '우' 소리가 있어요!" 만 F
... N O O ...   "우체통" 반복 세 줄이 N/O 로 쪼개짐
```

**원인**: 이미지 상속 규칙이 "그 **줄**의 첫 낱말이 원래 속했던 Vrew 클립의 이미지" 였다. Vrew 자동분할 클립(21~25개)과 대본 줄(34개)은 애초에 경계가 다르므로, 한 장면 도중에 그림이 바뀐다. `1.아` 만 멀쩡했던 건 이미지 생성 **전에 클립병합**을 거쳐 원본이 이미 14클립이었기 때문 — 병합 파이프라인의 부수 효과였다.

## 조치 — `inject-pause-v3.ps1` v3.1: 이미지를 "블록 단위"로 배정

규칙을 **"그 줄이 속한 대본 블록의 낱말 다수가 온 클립의 이미지"** 로 바꿨다. 한 블록의 모든 줄이 같은 그림을 쓴다.

- 대본의 빈 줄을 살려 블록 번호를 매기고(`$blockOf`), 줄마다 낱말별 원본 이미지를 순서대로 모은 뒤, 블록별로 최다 득표 이미지를 고른다(동률은 먼저 나온 것).
- 결과: 6개 회차 실측에서 전부 `34줄 = 14블록 → 이미지 14장`, 무음 개수는 변동 없음. `7.우` 는 `1.아` 와 완전히 같은 패턴이 됐다.
- **크레딧 0원.** 이미 생성돼 파일 안에 있는 이미지 중 어느 것을 쓸지 고르는 문제였을 뿐이다.
- `1.아` 는 원본이 이미 14클립이라 이 변경으로 결과가 달라지지 않는다.

부수 관찰: 병합 안 거친 회차는 파일 안에 20~25장이 들어 있지만 실제로 쓰이는 건 14장. 남는 6~11장은 파일 용량만 차지하고 내보내기 결과엔 영향 없음 — 따로 손대지 않았다.
