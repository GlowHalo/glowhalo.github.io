# 2026-08-19 — inject-pause.ps1 원본 코드 확인: 이미지 낭비의 진짜 지점 확정

## 배경
8/17 로그에서 "`inject-pause.ps1`/`run-all.ps1`이 실제로 이미지 병합(assetId 통일) 로직을 포함하는지 원본 코드 확인 필요 — 라온은 이 코드를 본 적 없음"으로 남겨둔 숙제. 회장이 오늘 `0.____.cmd`·`run-all.ps1`·`inject-pause.ps1` 3개 파일을 전달해 직접 읽고 확정했다.

## 파이프라인 실체 (코드 기준)
- `0.____.cmd` → `tools\run-all.ps1` 호출.
- `run-all.ps1`: 폴더의 `*_대본.txt` 마스터를 훑어 각 회차마다 `<name>.vrew`(Vrew 1차 생성본) + `<name>_대본.txt`를 짝지어 `inject-pause.ps1`을 돌리고 `<name>_완성.vrew`를 만든다. (`_완성.vrew`가 원본보다 최신이면 스킵 — 증분 재생성)
- `inject-pause.ps1`:
  1. `.vrew`(zip) 풀어 `project.json` 파싱.
  2. 기존 Vrew 클립들을 순회하며 **클립별 이미지 asset을 기억**(`$imgAsset`)하고 단어 스트림을 만든다.
  3. **`_대본.txt`의 한 줄 = 완성본 클립 1개**로 재구성. 각 재구성 클립의 이미지는 **그 줄의 첫 말단어가 원래 속했던 Vrew 클립의 이미지 1장만** 물려받는다(`if (-not $imgA) { $imgA = $e.img }`, 79번 줄). 같은 줄에 묶인 나머지 원본 이미지들은 결과 클립 `assetIds`에 안 들어간다 = **버려진다.**
  4. `<n>` 마커만큼 무음(pause) 삽입, 자막폰트 110 고정, 무결성 해시 재계산 후 재포장.

## 확정 결론 — "34장 생성해 14장만 쓴다"의 원인
- **병합 로직은 `inject-pause.ps1`이 이미 잘 하고 있다.** 문제는 병합이 아니라 **생성**이다.
- 이미지는 이 스크립트가 돌기 **전에**, 회장이 `_붙여넣기.txt`를 Vrew에 넣는 순간 **Vrew 자동분할로 이미 다 생성**된다(여기서 크레딧 소모). `inject-pause.ps1`은 그중 일부만 남기고 버릴 뿐, 생성량을 줄이지 못한다.
- 즉 스크립트를 고쳐도 크레딧 절감은 안 된다. **절감하려면 Vrew에 넣는 `_붙여넣기.txt` 자체를, 묶고 싶은 2~3줄을 한 덩어리로 만들어 Vrew가 애초에 그만큼만 생성하도록** 유도해야 한다.
