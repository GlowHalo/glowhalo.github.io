# 2026-08-23 — 무음삽입 스크립트 v3: "무음이 절반 넘게 안 들어가던" 버그 원인 규명·수정

## 증상
`!2_무음넣기.cmd` 로 10개 회차를 일괄 처리했더니 `done 10, failed 0` 으로 정상 종료했는데,
콘솔의 `verify: pauses` 값이 회차마다 **19 / 29 / 59** 로 제각각이었다.
대본의 마커 합계는 전 회차 거의 동일(`<1>`×41 + `<3>`×21 = **104**)이므로 104 이상이 나와야 정상.
실패로 보고되지 않아 **그대로 완성본으로 저장돼 있었다.**

## 실측 분석 (9.으 회차, `_완성.vrew` 를 뜯어서 대본과 1:1 대조)
- 원본 `9.으.vrew` 무음 12개 → 완성본 59개. 즉 **47개만 삽입**(정상값은 94개).
- 토큰(낱말) 단위로 대조하니 규칙이 정확히 드러났다:
  - **앞쪽 39토큰**(원본 클립 0~3, 원본 무음이 하나도 없는 구간): 마커가 없는 토큰까지 전부 1개씩 삽입 → `max(1, 마커값)`
  - **그 뒤부터**: 삽입량이 `마커값 − (지금까지 흡수한 원본 무음 누계)` 로 줄어듦.
    원본 무음을 2개 지나친 뒤로는 `<1>` 은 0개, `<3>` 은 1개만 삽입. 3개를 지나친 뒤로는 전부 0개.
- 즉 **① 마커값이 최소 1로 뻥튀기되고, ② 낱말별로 리셋돼야 할 "이미 있는 무음 개수"가 누적**되는 두 가지 어긋남.

## 원인
- v2 소스 자체는 (드라이브 실물을 내려받아 확인) 로직상 맞게 쓰여 있었고, **PowerShell 7 에서 돌리면 정상값 106개가 나온다**(라온이 리눅스에 pwsh 7.4.6 설치해 원본 vrew + 대본으로 실제 재현 검증).
- 그런데 회장 PC 는 `.cmd` → `powershell`(= **Windows PowerShell 5.1**)로 실행된다. 5.1 에서만 위 두 가지가 어긋났다.
- 의심 지점은 (a) 루프 안에서 자동변수 `$Matches` 에 의존해 마커를 읽는 방식, (b) 루프 지역변수 초기화 타이밍.
  5.1 의 정확한 내부 사유까지는 특정하지 못했지만, **그 두 의존을 없애면 재현되지 않는 구조**로 다시 짰다.

## 조치 — `inject-pause-v3.ps1` (신규, v2 는 폐기)
1. **마커 파싱을 루프 밖에서 한 번에** 처리. `$Matches` 자동변수 대신 `[Regex]` 객체 + `$mm.Groups[n].Value` 사용.
2. **낱말별 "이미 있는 무음" 카운터를 `[int]` 로 명시 선언**하고 낱말마다 새로 만든다. 채우기 루프도 `for` → `while ($have -lt $want)`.
3. **모든 숫자를 InvariantCulture 로 출력**(소수점이 쉼표인 로캘에서 json 이 깨지는 잠재 버그 예방). null 도 0 으로 안전 처리.
4. **★ 자기검증 추가** — 결과 json 을 다시 파싱해 무음 개수를 세고, 기대값(`Σ max(마커, 기존무음)`)과 다르면 **throw 로 실패 처리**. 이제 이번 같은 조용한 부분실패는 파일이 아예 안 만들어지고 콘솔에 빨간 글씨로 뜬다.
5. 파일 전체를 **ASCII 로만** 작성(한글 주석 제거). BOM 없는 .ps1 을 5.1 이 ANSI 로 읽는 변수를 원천 차단.

`run-all-v3.ps1` 도 함께 교체: **injector 파일이 완성본보다 최신이면 무조건 재생성**(스크립트를 고쳤는데 "이미 최신"으로 건너뛰는 사고 방지), 실패한 회차 이름을 마지막에 모아서 출력.
