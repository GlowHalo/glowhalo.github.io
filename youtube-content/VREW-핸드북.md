# Vrew 핸드북 (GlowHalo 5 정본)

몬스터트럭 파닉스 파이프라인을 굴리기 위해 라온이 정리한 Vrew 지식 베이스. **실측으로 확인한 것과 공개자료·추정을 구분해 적는다.** 새 세션은 Vrew 관련 판단 전에 이 문서를 먼저 읽는다.

*최초 작성 2026-08-22 (Vrew 4.4.6 기준)*

## 1. 크레딧 모델

### 공식 (2026-04-22 통합 크레딧 개편)
기능별 사용량을 따로 주던 방식이 폐지되고 **하나의 크레딧 풀**로 통합됐다.

| 항목 | 1크레딧 = |
|---|---|
| 음성분석 | 1분 |
| AI 목소리(TTS) | 100자 |
| 번역 | 300자 |
| AI 이미지 / AI 비디오 | 개편 전과 동일(별도 단가, 공식 수치 비공개) |

- 요금제별 월 크레딧: **Free 200 / Light 2,000(14,900원) / Standard 10,000(23,900원)**
- 갱신: 무료는 매월 1일, 유료는 결제일. **이월 없음.**
- **내보내기는 크레딧 미소모**(무료 플랜도 무제한).
- 출처: [Vrew 요금정책](https://vrew.ai/ko/payment/pricepolicy), [통합크레딧 정리 블로그](https://yuksunglife.com/vrew-subtitle-video-editor-guide/)
- 공식 웹 문서엔 이미지 단가가 없지만, **Vrew 앱 3단계 화면에 모델별 단가가 직접 표시된다**(아래 확정값).

### ★ AI 이미지 단가 확정 (2026-08-22, Vrew UI 실물 확인)
3단계 [비디오 꾸미기] 화면의 **생성 모델 옆에 단가가 표시된다.**

| 항목 | 단가 |
|---|---|
| **GPT Image 2 Low** | **5 크레딧 / 이미지** |
| **고화질 ON** | **+1 크레딧 / 이미지** |
| **우리 표준 합계** | **6 크레딧 / 이미지** |

**검증**: 2026-08-17 ㅕ회차 실측 이미지 크레딧 **138** ÷ 6 = **23장** → 실제 `4.여.vrew`의 PNG가 정확히 **23장**. 완전 일치로 단가 확정.
(TTS는 같은 회차에서 9크레딧 — 이미지의 1/15 수준이라 사실상 무시 가능. "비싼 건 이미지뿐"이 수치로 확정됨.)

### 회차 비용 계산법
`회차 크레딧 ≈ 클립 수 × 6`
| 회차 | 클립 | 크레딧 |
|---|---|---|
| 어(마침표 제거) | 21 | 126 |
| 이·우 | 22 | 132 |
| 여·요·으 | 23 | 138 |
| 유 | 24 | 144 |
| 오 | 25 | 150 |

- **마침표 2개 제거 = 2클립 = 12크레딧/회차 절감**
- 남은 56회차(복합모음 11 + 자음 19 + 알파벳 26)에 적용하면 **약 670크레딧 절감**
- 전체 66회차 총비용 추정: 약 **8,700크레딧** ≈ Standard 플랜(월 10,000) **한 달치**

## 2. 프로젝트 생성 경로와 각 단계에서 실제로 벌어지는 일

`새로 만들기 → 텍스트로 비디오 만들기` 마법사는 3단계다.

| 단계 | 하는 일 | 크레딧 |
|---|---|---|
| ① 스타일 고르기 | 이미지 화풍·비율 선택 | - |
| ② 대본 작성 | 텍스트 붙여넣기 (직접 입력 또는 AI 글쓰기) | AI 글쓰기 쓸 때만 |
| ③ 비디오 꾸미기 | **클립 자동 분할 + TTS 생성 + AI 이미지 자동 생성** | **여기서 전부 소모** |

### ★ 3단계 [비디오 꾸미기] 실제 옵션 (2026-08-22 화면 확인 — 초기 판단 정정)
| 항목 | 값 | 토글 |
|---|---|---|
| 화면 비율 | **16:9** / 9:16 / 1:1 / 4:5 / 4:3 | - |
| AI 목소리 | 자몽(보통) | **ON/OFF 가능** |
| 배경음악 | 활기찬 | **ON/OFF 가능** |
| **AI 이미지** | GPT Image 2 Low (5크레딧/장) + 프롬프트 + 고화질(+1) | **★ ON/OFF 가능** |
| 무료 비디오 | - | OFF |

### ✅ AI 이미지 토글 — 검증 완료, 절감 경로 확정 (2026-08-22)

**3단계 [비디오 꾸미기]의 `AI 이미지` 토글을 OFF로 두고 [완료]를 누르면 이미지 0장으로 초안이 생성된다.** 회장이 `1.아`로 실제 테스트, 라온이 파일 해부로 확인:

| | `1.아_test.vrew` (토글 OFF) | `2.야.vrew` (평소대로) |
|---|---|---|
| 파일 크기 | **3.50MB** | 14.88MB |
| PNG | **0장** | 22장 |
| image track | **0개** | 22개 |
| 클립 | 23 | 22 |
| TTS(ttsClip) | 247 | 254 |
| BGM | 있음 | 있음 |

→ **대본·음성·BGM·클립 구조는 전부 정상이고 이미지만 빠진다.** 이미지 크레딧 0으로 초안 확보 가능.

**병합 전제조건도 검증 완료**: `1.아_test`의 말단어 232개 = `1.아_대본.txt` 토큰 232개 일치, 대본 블록 14개와 클립 경계 정합 OK → `merge-clips.ps1` 안전하게 적용 가능.

**절감 확정**: 23장(138크레딧) → 14장(84크레딧) = **회차당 54크레딧, 39% 절감.**

## 3. 클립 분할 규칙 ★ 실제 `.vrew` 해부로 확정 (2026-08-22)

`10.이.vrew` 원본을 R2로 받아 압축 해제 후 `project.json`을 직접 분석해 **붙여넣기 14줄 → 22클립**이 어떻게 갈라졌는지 1:1로 대조했다.

**AI 이미지는 클립 1개당 정확히 1장.** (실측: 클립 22개 = PNG 22장) 즉 **생성 이미지 수 = 이미지 삽입 시점의 클립 수**이고, 클립 수 통제가 곧 비용 통제다.

### 분할을 일으키는 두 가지 요인
**① 길이 상한 — 클립 하나는 약 60자를 넘지 않는다**
8개 회차 179개 클립 실측: 최대 **60자**, 평균 39자, 57자 초과는 8개뿐. 붙여넣기 한 줄이 이보다 길면 잘린다.

**② 마침표(`.`)는 상한 미만에서도 분할을 일으킨다** ← 새 발견
| 줄 | 글자 | 내부 `.` | 내부 `!?` | 결과 |
|---|---|---|---|---|
| 3 | 56자 | 0 | 1 | **1클립** |
| 5 | 53자 | 0 | 0 | **1클립** |
| 7 | 49자 | 0 | 0 | **1클립** |
| 9 | 54자 | 0 | 0 | **1클립** |
| 11 | 52자 | 0 | 0 | **1클립** |
| 14 | 36자 | 0 | 0 | **1클립** |
| **13** | **55자** | **1** | 1 | **2클립** ★ |

- 56자짜리도 1클립으로 버티는데 **55자짜리가 쪼개졌다.** 차이는 문장 중간의 **마침표** 하나뿐. 실제 분할 지점도 `찾았네요.` 직후였다.
- **`!`와 `?`는 분할을 일으키지 않는다** — 위 표에서 물음표·느낌표만 있는 줄 6개가 전부 1클립 유지(대조군 6건).
- 길이로 잘릴 때는 쉼표·느낌표 등 가까운 경계를 골라 자르지만, 경계가 없으면 문장 중간에서도 자른다(1줄: "…오늘은 '이' 소리 | 친구를, 다섯 명…").

### 💰 즉시 적용 가능한 절감안
우리 템플릿에는 **문장 중간 마침표가 딱 2개**뿐이다 — `좋아요.` 와 `찾았네요.`
이 둘을 `!`로 바꾸면 **회차당 2클립(≈8크레딧) 절감**, 22 → 20클립. 유아 대상이라 `좋아요!`·`찾았네요!`가 억양상 오히려 자연스럽다. **부작용 없는 순수 이득.**


### ✅ 2026-08-22 대규모 검증 — 8개 회차 실측으로 모델 확정

회장이 `.vrew` 8개(어·여·오·요·우·유·으·이)를 R2로 전달, 전부 해부해 대조했다.

**예측식**: `클립 수 = Σ max( ⌈줄 글자수 ÷ 60⌉ , 그 줄의 내부 마침표 수 + 1 )`

| 회차 | 예상 | 실측 | 오차 |
|---|---|---|---|
| 3.어 | 21 | **21** | 0 |
| 5.오 | 25 | **25** | 0 |
| 6.요 | 23 | **23** | 0 |
| 7.우 | 21 | 22 | −1 |
| 9.으 | 22 | 23 | −1 |
| 10.이 | 22 | **22** | 0 |

6개 중 4개 정확, 2개는 1클립 오차. **cap=60일 때 오차 최소**(56~62 전부 비교해 확정). 이제 만들기 전에 비용을 계산할 수 있다.

### 🏆 마침표 제거 효과 — 대조군으로 증명됨
| 회차 | 총글자 | 마침표 | 클립 | 글자/클립 |
|---|---|---|---|---|
| **3.어** | 886 | **0** | **21** | **42.2** |
| 6.요 | 887 | 2 | 23 | 38.6 |
| 9.으 | 892 | 2 | 23 | 38.8 |
| 10.이 | 877 | 2 | 22 | 39.9 |

**어(886자)와 요(887자)는 글자 수가 사실상 같은데 21 vs 23** — 유일한 차이가 마침표 2개다. **마침표 2개 제거 = 2클립(≈8크레딧) 절감 확정.**
→ **표준 채택**: 모든 신규 회차는 문장 중간 마침표를 `!`로 바꾼다(`좋아요!` `찾았네요!`). 유아 대상이라 억양상으로도 낫다.

### 회차별 실측 클립 수 (2026-08-22)
어 21 · 이 22 · 우 22 · 여 23 · 요 23 · 으 23 · 유 24 · 오 25
(어만 마침표 제거 적용. 오가 최다인 건 낱말이 길어서 — 오징어·오뚝이·오토바이)

### 실질 하한
- 이론 최소 = 총글자 ÷ 56 ≈ 16클립. 다만 거기까지 가려면 한 클립이 **장면 경계를 넘나들어** "트럭 등장"과 "낱말 부르기"가 한 이미지에 섞인다.
- **장면 정렬을 지키는 한 20~25가 실질 바닥**(마침표 제거 적용 시 20~23).
- 낱말이 길수록(오징어·오뚝이·오토바이) 클립이 는다 — 대본에서 오는 차이라 회피 불가.

### 검증 이력 (전부 실측, 실패한 시도 포함)
- 줄바꿈으로 통제 → 실패. Vrew는 우리 줄바꿈을 무시하고 재분할(ㅛ 14줄 → 23클립).
- 종결부호 전체를 쉼표로 치환 → 22클립. 1개만 줄었는데 **그 1개가 바로 마침표 효과**였음이 이번에 규명됨.
- ≤55자로 미리 재분할 → 이득 0(자투리 줄이 생겨 총량 동일).

### 수동 조절
**[클립 합치기] / [클립 나누기]** 로 사후 조절 가능하나, 이미지 생성 **후**라 크레딧은 이미 나간 뒤다. 남는 이미지는 `inject-pause`가 자동으로 버리므로 최종 품질에는 영향 없다.

## 4. AI 이미지

- **모델·스타일**: 스타일 15종 제공(사실적 사진 ~ 추상). 우리 표준은 **GPT Image 2 Low / 3D모델 / 고화질 ON** (Notion 세팅값 문서).
- **[이미지 프롬프트]**: 삽입되는 이미지 **전체의 분위기**를 지정하는 필드. **시리즈 톤 일관성의 핵심.**

### ⚠️ 프롬프트는 어떤 파일에도 저장되지 않는다 (2026-08-22 확인)
`.vrew`의 `project.json`을 전수 검색해도 **프롬프트 문자열이 없다**(8개 회차 전부 확인). Vrew **앱 설정에만** 살아있다.
→ **앱을 재설치하거나 설정이 초기화되면 시리즈 이미지 톤을 재현할 수 없다.** 반드시 저장소에 원문을 남겨둘 것.

**우리 시리즈 표준 프롬프트 — 정본** (2026-08-22 회장이 전문 확인·제공):
```
cute cartoon monster truck character with big round wheels and a friendly smiling face, Pixar-style 3D render, bright saturated colors, soft even lighting, pastel background, wholesome and friendly, no scary elements, for toddlers
```
구성 의도: `캐릭터 형태(둥근 큰 바퀴·웃는 얼굴)` + `렌더 스타일(픽사풍 3D)` + `색·조명(선명한 채도, 부드러운 균일 조명, 파스텔 배경)` + `정서 안전장치(따뜻함, 무서운 요소 금지, 유아 대상)`.
**전 회차 이 문자열을 그대로 쓴다.** 한 회차만 달라지면 시리즈 톤이 튄다.

### [삽입 > AI 이미지] 대화상자 (병합 후 이미지를 넣을 때)
마법사와 **별도 설정**이라 값이 기본값으로 뜰 수 있다. 매번 아래를 맞출 것:
| 항목 | 값 |
|---|---|
| 적용 범위 | 전체 클립 |
| 생성 모델 | GPT Image 2 Low (5크레딧/장) |
| 프롬프트 | 위 표준 프롬프트 |
| 스타일 | **3D모델** |
| 고화질 | ON (+1크레딧/장) |
- **개별 교체**: 마음에 안 드는 이미지는 (a) AI에게 추가 수정 요청, (b) 삭제 후 `삽입 → 무료 이미지/비디오`에서 에셋 더블클릭으로 교체.
- **일괄 삽입**: `삽입 → AI 이미지 자동삽입 → 전체클립`. **한 번에 10클립씩** 처리된다.

## 5. AI 목소리(TTS) ★ 2026-08-22 확정

**텍스트를 바꾸면 음성이 그에 맞춰 다시 생성된다. 비용은 사실상 무료 수준.** (회장 확인)

이게 파이프라인 전체에서 가장 중요한 사실이다:
- **대사 수정 = 공짜.** 이미 만든 회차의 대본을 고쳐도 이미지를 다시 만들 필요가 없다.
- 즉 **비싼 것은 이미지 하나뿐**이고, 텍스트·자막·무음·억양은 얼마든지 손봐도 된다.
- 우리 `inject-pause-v2`가 자막을 대본 원문으로 복원하는 것도 이 성질 위에서 안전하게 돌아간다.

**활용 여지(미탐색)**: 이미지가 이미 잘 붙어 있는 기존 vrew에서 **대사만 갈아끼우는** 재활용이 원리상 가능하다. 걸림돌은 `inject-pause`가 요구하는 **단어 수 일치** 하나뿐 — 스크립트를 고치면 열릴 수 있는 길.

## 7. `.vrew` 파일 포맷 — 실물 해부 결과 (2026-08-22, version 17)

`10.이.vrew`(15.6MB) 실물을 뜯어 확인한 구조. **압축 방식은 `store`(무압축) ZIP.**

```
project.json          160KB  ← 프로젝트 전체 구조
media/<mediaId>.mp3    22개  ← TTS 음원 (클립당 1개)
media/<uuid>.png       22개  ← AI 생성 이미지 (클립당 1장)
media/mewpot_bgm_*.mp3  1개  ← 배경음악
```

### project.json 최상위
`version`(=17) / `files` / `transcript` / `props` / `comment` / `projectId` / `statistics` / `integrity`

### 4층 참조 구조
```
clip.assetIds[]  →  props.assets[id].trackIds[]  →  props.tracks[id].mediaId  →  media/ 파일
word.assetIds[]  →  (같은 경로)                  →  ttsClip track (mp3 구간)
```
- `props.assets` / `props.tracks` 각각 **261개** = ttsClip 238 + image 22 + bgm 1
- **클립**은 `assetIds`에 이미지 1 + BGM 1을 물고 있다(`role: "sub"`)
- **단어**는 각자 `assetIds`로 ttsClip track을 물고, 그 track은 **클립 mp3의 시간 구간**(`sourceIn`~`sourceOut`)을 가리킨다
  → 즉 **음성은 단어별 파일이 아니라, 클립 단위 mp3 하나를 단어 수만큼 잘라 쓰는 구조**

### ⚠️ Windows 스크립트 인코딩 함정 (2026-08-22 실제 사고)
`1단계_클립병합.cmd`에 한글(대화형 프롬프트, `_대본.txt` 경로)을 넣었더니 cmd.exe가 파싱을 깨뜨려 `powershell`이 `powers`+`hell`로 쪼개지며 실행 실패했다.
**원인**: cmd.exe는 파일을 OEM 코드페이지(한국어 윈도우=CP949)로 읽는데 파일이 UTF-8이라 멀티바이트 한글이 깨진다. `chcp 65001`은 이미 늦다.

**확정 규칙**
1. **`.cmd` 파일 내용은 ASCII만** — 한글 프롬프트·한글 경로 리터럴 금지. 경로 조합은 전부 `.ps1`에 맡긴다. (파일명 자체의 한글은 무관)
2. **`.cmd`는 대화형 입력(`set /p`)을 쓰지 않는다** — 폴더를 스캔하는 방식으로 대체.
3. **`.ps1`은 UTF-8 BOM + CRLF로 저장** — Windows PowerShell 5.1은 BOM 없는 파일을 ANSI(949)로 읽어 한글 문자열이 깨진다.
4. **`.ps1`의 실행 로직에는 한글 리터럴을 쓰지 않는다** — 파일명 접미사가 필요하면 문자코드로 조립한다:
   `$SUF = [string]([char]0xB300) + [string]([char]0xBCF8)  # 대본`
   이러면 인코딩이 깨져도 기능은 살아남는다. (콘솔 메시지도 되도록 영문)

### 안전장치
`inject-pause`는 **대본 토큰 수 ≠ vrew 단어 수이면 즉시 실패**(`word count mismatch`)한다. 잘못된 조합으로 파일이 깨지는 사고를 원천 차단하며, 회차별로 독립 실패해 다른 회차에 영향이 없다.
