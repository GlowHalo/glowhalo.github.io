# Vrew 핸드북 (GlowHalo 5 정본)

몬스터트럭 파닉스 파이프라인을 굴리기 위해 라온이 정리한 Vrew 지식 베이스. **실측으로 확인한 것과 공개자료·추정을 구분해 적는다.** 새 세션은 Vrew 관련 판단 전에 이 문서를 먼저 읽는다.

*최초 작성 2026-08-22 (Vrew 4.4.6 기준)*

### 실측 (우리 회차 기준)
| 회차 | 조건 | 이미지 | 목소리 | 합계 |
|---|---|---|---|---|
| ㅕ(여) | 34줄, 2,084자, 이미지 ~34장 | 138 | 9 | 147 |

- 이미지 환산: **약 4크레딧/장** (138 ÷ 34). 회차당 21~25장이면 **약 85~100크레딧**.

- **핵심**: 비용의 90% 이상이 이미지다. 아껴야 할 것은 오직 이미지 생성 수량.

## 2. 프로젝트 생성 경로와 각 단계에서 실제로 벌어지는 일

`새로 만들기 → 텍스트로 비디오 만들기` 마법사는 3단계다.

| 단계 | 하는 일 | 크레딧 |
|---|---|---|
| ① 스타일 고르기 | 이미지 화풍·비율 선택 | - |
| ② 대본 작성 | 텍스트 붙여넣기 (직접 입력 또는 AI 글쓰기) | AI 글쓰기 쓸 때만 |
| ③ 비디오 꾸미기 | **클립 자동 분할 + TTS 생성 + AI 이미지 자동 생성** | **여기서 전부 소모** |

**⚠️ 가장 중요한 제약 (2026-08-22 실측 확인)**: 3단계에는 **이미지 자동삽입을 끄는 옵션이 없다.** 편집 화면에 도착한 시점엔 이미 이미지가 다 생성돼 크레딧이 나간 뒤다.
→ 따라서 **"이미지 생성 전에 클립을 병합해 수량을 줄인다"는 전략은 이 경로에서 성립하지 않는다.** (merge-clips.ps1을 만들었다가 투입 시점이 없어 폐기한 이유)

## 3. 클립 분할 규칙 ★ 우리가 직접 밝혀낸 것

**AI 이미지는 클립 1개당 정확히 1장** 생성된다. 즉 **생성 이미지 수 = 이미지 삽입 시점의 클립 수**. 그래서 클립 수 통제가 곧 비용 통제다.

### 분할 기준 = 붙여넣기 한 줄의 **글자 수** (구두점 종류 무관)
| 한 줄 길이 | 결과 |
|---|---|
| ~57자 이하 | 1클립 유지 |
| 58~110자 | 2클립으로 분할 |
| 111자 이상 | 3클립으로 분할 |

**검증 이력 (전부 실측)**
- 줄바꿈으로 통제 시도 → 실패. Vrew는 우리 줄바꿈을 무시하고 재분할한다. (ㅛ 14줄 → 23클립)
- 종결부호를 쉼표로 치환 → 실패. `.!?`와 `,`는 분할에 영향 없음. (ㅜ 14줄 쉼표판 → 22클립)
- ≤55자로 미리 재분할 → **이득 0**. 자투리 줄(6~9자)이 생겨 총 클립 수가 그대로. (ㅗ 계산상 25 → 25)

### 실질 하한
- 이론 최소 = 총글자 ÷ 57 ≈ **16~17클립**.
- 그러나 거기까지 가려면 한 클립이 **장면 경계를 넘나들게** 글자를 채워야 하고, 그러면 "트럭 등장"과 "낱말 부르기"가 한 이미지에 섞여 품질이 깨진다.
- **결론: 장면 정렬을 지키는 한 21~25클립이 실질 바닥.** 회차별 실측/예상 — 아 24 / 야 25 / 어 23 / 여 · 오 25 / 요 23 / 우 22 / 으 23 / 이 21.
- 낱말이 길수록(오징어·오뚝이·오토바이) 클립이 늘어난다. 대본 내용에서 오는 차이라 회피 불가.

### 수동 조절
- **[클립 합치기]** / **[클립 나누기]** 로 사후 조절 가능(우클릭 또는 상단 버튼). 다만 이미지 생성 **후**라 크레딧은 이미 나간 상태.
- 남는 이미지는 우리 `inject-pause`가 자동으로 버리므로 **최종 품질에는 영향 없다.**

## 4. AI 이미지

- **모델·스타일**: 스타일 15종 제공(사실적 사진 ~ 추상). 우리 표준은 **GPT Image 2 Low / 3D모델 / 고화질 ON** (Notion 세팅값 문서).
- **[이미지 프롬프트]**: 삽입되는 이미지 **전체의 분위기**를 한 번에 지정하는 필드. 예) "한복을 입은 사람들", "동양인". → **시리즈 톤 일관성 유지에 쓸 수 있는 미탐색 레버.**
- **개별 교체**: 마음에 안 드는 이미지는 (a) AI에게 추가 수정 요청, (b) 삭제 후 `삽입 → 무료 이미지/비디오`에서 에셋 더블클릭으로 교체.
- **일괄 삽입**: `삽입 → AI 이미지 자동삽입 → 전체클립`. **한 번에 10클립씩** 처리된다.

## 5. AI 목소리(TTS) ★ 2026-08-22 확정

**텍스트를 바꾸면 음성이 그에 맞춰 다시 생성된다. 비용은 사실상 무료 수준.** (회장 확인)

이게 파이프라인 전체에서 가장 중요한 사실이다:
- **대사 수정 = 공짜.** 이미 만든 회차의 대본을 고쳐도 이미지를 다시 만들 필요가 없다.
- 즉 **비싼 것은 이미지 하나뿐**이고, 텍스트·자막·무음·억양은 얼마든지 손봐도 된다.
- 우리 `inject-pause-v2`가 자막을 대본 원문으로 복원하는 것도 이 성질 위에서 안전하게 돌아간다.

**활용 여지(미탐색)**: 이미지가 이미 잘 붙어 있는 기존 vrew에서 **대사만 갈아끼우는** 재활용이 원리상 가능하다. 걸림돌은 `inject-pause`가 요구하는 **단어 수 일치** 하나뿐 — 스크립트를 고치면 열릴 수 있는 길.

## 7. `.vrew` 파일 포맷 (우리가 스크립트로 직접 조작하는 부분)

`.vrew`는 **ZIP 아카이브**다.
```
project.json      ← 프로젝트 전체 구조 (텍스트)
media/            ← 실제 음원·이미지 파일들
```

### project.json 핵심 구조
- `transcript.clips[]` — 클립 배열. 각 클립:
  - `words[]` — 단어 단위 배열. **`type 0`=말, `type 1`=무음, `type 2`=클립 종료 표시**
    - 각 word: `id`, `text`, `duration`, `originalDuration`, `originalStartTime`, `assetIds[]`
  - `captions[]` — 화면 자막(Quill 델타 형식, `{"insert":"..."}`)
  - `assetIds[]` — 이 클립이 쓰는 에셋(이미지·BGM)
  - `sceneId`, `captionMode`, `dirty`
- `props.assets{}` — assetId → `{trackIds[], role}`
- `props.tracks{}` — trackId → `{mediaId, type, sourceIn, sourceOut, volume, ...}`
  - `type`: `image` / `bgm` / `ttsClip`
- `integrity` — **SHA256 무결성 해시.** 이 값을 빈 문자열로 만든 상태의 JSON 전체를 해싱해 다시 채워 넣어야 파일이 열린다. (우리 스크립트가 이 절차를 구현)

### 우리 도구
| 파일 | 역할 |
|---|---|
| `inject-pause-v2.ps1` | `.vrew` + `_대본.txt` → 대본 줄 단위로 클립 재구성, `<n>` 마커만큼 무음 삽입, 자막을 대본 원문으로 복원, 폰트 110 적용, 무결성 재계산 후 재포장 |
| `run-all-v2.ps1` | 폴더의 모든 `*_대본.txt`를 훑어 짝이 되는 `.vrew`가 있으면 일괄 처리 |
| `무음넣기_전체.cmd` | 위 실행기 (더블클릭) |

### 안전장치
`inject-pause`는 **대본 토큰 수 ≠ vrew 단어 수이면 즉시 실패**한다(`word count mismatch`). 잘못된 조합으로 파일이 깨지는 사고를 원천 차단하는 설계이며, 회차별로 독립 실패하므로 다른 회차에 영향이 없다.

## 8. 우리 파이프라인 표준 (현재 확정판)

1. Notion 트래커에서 회차 대본 확정
2. 라온이 `N.글자_대본.txt`(마커 포함, 34줄) + `N.글자_붙여넣기.txt`(마커 제거, 14줄) 생성 → **토큰 수 일치 검증** 후 Drive 작업폴더 배치
3. 회장이 Vrew에서 붙여넣기 → `N.글자.vrew`로 저장 (이미지·TTS 여기서 생성)
4. `무음넣기_전체.cmd` 실행 → `N.글자_완성.vrew`
5. 회장이 1080p 내보내기
6. 유튜브 업로드

**작업폴더**: Google Drive `몬스터카파닉스` (id `1ZygyPfSHBUMGjBWJ8nNcIlx9RvpJcU38`). 라온이 Drive API로 직접 읽고 쓴다.
