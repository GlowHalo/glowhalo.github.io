# PocketCrew — GlowHalo 14

**담당: 보람** (2026-08-26 선임, 신사업논의방/다온에서 분리). 공유 원칙(회장 리소스 제약, 공개저장소 주의, 조직 확장은 사후 기록·사전 승인 불필요, 신규 역할은 실명 없이 역할명만, 신규 계정 가입은 회장 요청 기반)은 루트 [`CLAUDE.md`](../CLAUDE.md)와 [`niche-templates/README.md`](../niche-templates/README.md)를 그대로 따른다. 이 문서는 PocketCrew만의 차이점만 적는다.

## 한 줄 정의

**"내 클로드 계정으로 실제 돌아가는 AI 팀을, 귀여운 픽셀 오피스로 보고 지시하는 컴패니언 앱."**

- 영문 정식명: **PocketCrew**
- 태그라인(항상 병기): **"Create My AI Office"** / 국문 **"나만의 AI오피스 만들기"**(줄임 애칭: **나오만**)
- 타겟: 클로드를 재밌게 잘 쓰고 싶은 **비개발자**
- UI 메타포: "팀 생성" = claude.ai 세션 생성, "직원 고용" = 세션 내 에이전트(역할) 추가

## 왜 신설했나 — venture-lab에서 분리된 경위

`venture-lab/`(다온, GlowHalo Group 신사업 논의방)에서 2026-08-22~08-26 사이 논의·검증을 거쳐 확정. 전체 논의 원문·리서치 과정은 [`venture-lab/candidates.md`](../venture-lab/candidates.md)의 "② 우리 운영구조를 귀여운 UI로 상품화" 이하 항목에 보존돼 있다 — 이 문서는 그 논의의 **결과만** 정리한 것이고, "왜 이 결정에 도달했는지"의 전체 맥락이 필요하면 그쪽을 참고할 것.

## 확정된 기술 구조 — "템플릿+뷰어" 아키텍처

우리 앱은 클로드 API를 직접 호출하지 않는다. 대신:

1. 사용자가 GitHub 계정으로 우리 앱에 연결하고, 우리 템플릿 저장소를 본인 계정에 복사(generate-from-template)한다.
2. **"Claude Code에서 열기"** 버튼 → `https://claude.ai/code?repositories=<user>/<repo>&prompt=...` (claude.ai/code 공식 프리필 딥링크, [문서](https://code.claude.com/docs/en/web-quickstart#pre-fill-sessions)) → 새 탭에서 claude.ai가 열리고, 사용자가 **본인 Pro/Max 구독으로 직접 로그인**해 템플릿을 실행한다.
3. 로그인·세션 생성·실제 작업은 전부 그 탭 안, 우리 앱 밖에서 일어난다 — 우리 앱은 claude.ai 로그인에 관여하지 않는다(Anthropic 정책상 제3자가 로그인을 대신 제공하는 것은 금지).
4. claude.ai 세션이 작업하며 저장소에 **상태파일**을 남긴다. 우리 앱(뷰어)은 GitHub API로 그 저장소를 주기적으로 **읽기만** 해서 픽셀오피스 화면으로 그려준다 — 클로드와 직접 통신하지 않는다.
5. 사용자가 뷰어에서 새 지시를 입력하면 앱이 GitHub API로 **지시사항.md**에 직접 커밋한다. 사용자가 다음에 claude.ai에서 그 저장소를 다시 열면 클로드가 그 파일을 읽고 처리한다 — **비동기 루프, 실시간 아님.**
6. 이 구조 덕분에 claude.ai 자체 화면·구독 그대로 사용 → 최근(2026-06-15) 생긴 "프로그래매틱 사용 전용 별도 크레딧" 과금 대상이 **아님**(공식 도움말로 확인 완료) — 사용자는 원래 내던 구독료 안에서 그대로 쓴다.

구조 다이어그램(발행본): [`design/architecture-diagram.html`](design/architecture-diagram.html)

**남은 마찰 포인트(정직하게 기록)**: 사용자가 GitHub 계정을 갖고 있어야 하고, 템플릿을 본인 계정으로 복사하는 단계가 필요함 — 비개발자 타겟에게 작은 진입장벽. 지금은 그대로 진행, 문제되면 재상의.

## 확정된 사용자 여정 — 화면 흐름 S0~S7

| # | 화면 | 내용 |
|---|---|---|
| S0 | 첫 실행 안내 | "클로드로 실제 작동" 설명 + 필요 조건(GitHub 계정·클로드 구독) 안내 |
| S1 | GitHub 연결 | 표준 GitHub OAuth, 우리 앱 밖 팝업 — claude.ai 로그인이 아니라 GitHub 로그인이라 정책 문제 없음 |
| S2 | 팀 만들기 | 저장소 이름 입력 → 우리 앱이 GitHub API로 템플릿을 사용자 계정에 자동 복사 |
| S3 | 직원 고용(선택) | 역할 프리셋 체크 → 저장소 CLAUDE.md에 반영, 스킵 가능 |
| S4 | Claude Code에서 열기 | 프리필 딥링크로 새 탭 오픈. 최초 사용자는 claude.ai 자체 로그인+GitHub 연결이 한 번 더 뜸(claude.ai 쪽 1회성 절차, 우리 앱과 무관) |
| S5 | 뷰어 복귀 | GitHub API로 상태파일 주기적 폴링 → 픽셀오피스 렌더링, "마지막 갱신 n분 전" 표시로 비실시간임을 은연중 전달 |
| S6 | 지시 입력 | 뷰어 입력창 → 저장 시 우리 앱이 GitHub API로 지시사항.md 직접 커밋 |
| S7 | 재개 안내 | "다시 열어주세요" + S4 딥링크 재사용 버튼. **MVP는 예약 자동 재개 없이 수동 재개로 시작** — 자동화(Routines 활용)는 이후 과제 |

## 확정된 로드맵 — 픽셀 먼저, 3D는 반응 보고 애드온

1. **1차 출시: 코지 픽셀아트 MVP.** 위 화면 목업 톤 그대로. 개발비가 가장 낮고 이미 검증됨.
2. **개발 시 지킬 원칙**: 직원·데스크·방 배치 등을 픽셀 렌더러 코드에 하드코딩하지 말고 **데이터로 분리**해둔다 — 나중에 3D 렌더러를 얹을 때 데이터 모델을 두 번 설계하지 않기 위함.
3. **2차(반응 확인 후): 3D 프리미엄 애드온.** 회장이 3D 쪽에 더 끌린다고 밝혔고("회사 역량을 끌어올리는 테스트 겸" 실제로 조사·프로토타입까지 완료), 다만 매출·사용자 신호가 생긴 뒤 투자하는 게 리스크가 낮다고 판단해 순서를 이렇게 정함.
   - **3D 실현 가능성 조사 결과**: 프리랜서 3D 아티스트 고용($1,200~15,000+/캐릭터)이나 유료 에셋팩(Synty 등, 팩당 $50~200대 + 별도 엔진 통합 개발)은 예산 원칙 밖. **무료 CC0 경로(Kenney 에셋 + Three.js)만 지금 예산으로 실행 가능**하다고 판단해 실제로 조사·검증까지 마침.
   - **실제로 작동하는 3D 프로토타입 완성**: Kenney "Furniture Kit"(CC0, glb 23종)을 Three.js(WebGL)로 조립, 엔진 전체를 하나의 HTML 파일에 번들링(외부 의존성 없음, 904KB). 발행본: [`design/3d-prototype.html`](design/3d-prototype.html)
   - **확인된 한계**: 화풍이 "심즈 사실적"이 아니라 로우폴리 미니멀 톤. 캐릭터는 리깅된 휴머노이드 대신 원기둥+구로 만든 심플한 도형(무료 캐릭터팩을 못 찾음) — 이 부분이 3D를 실제 상품화할 때 가장 먼저 보강해야 할 지점.
4. **파킹된 아이디어**: "3D 미니어처 타일"(책상 하나하나를 개별 디오라마 타일로) — 방 전체 씬보다 구현 범위가 작을 수 있어 3D 착수 시 유력 후보. 아직 검토 전.

## 개발 중 결정 (2026-08-26)

- **S1 GitHub 연결 방식을 "표준 OAuth 팝업" 대신 "사용자가 직접 발급한 Personal Access Token(classic, repo 권한) 붙여넣기"로 구현.** 이유: OAuth 인가코드→토큰 교환에는 client_secret을 숨길 백엔드(Cloudflare Worker)가 필요한데, PAT 방식은 브라우저 fetch만으로 GitHub REST API(CORS 지원)를 직접 호출할 수 있어 백엔드 없이 픽셀 MVP를 오늘 바로 동작시킬 수 있었다. UI상 S1 화면 하나만 다르고 S2 이후 로직(저장소 생성, 파일 커밋, 상태 폴링)은 완전히 동일하므로, 나중에 정식 OAuth 앱 + Worker를 붙여도 이 화면만 교체하면 된다.
- **"템플릿 저장소에서 generate" 대신 "빈 저장소 생성 + Contents API로 파일 직접 커밋" 방식 채택.** 진짜 GitHub 템플릿 저장소(별도 공개 repo, `is_template` 설정)를 아직 만들지 않았고, 이 세션의 GitHub 접근 권한이 이 모노레포로 제한돼 있어 새 저장소를 만들어 검증하기 어려웠다. 대신 `app/templates/`(CLAUDE.md·README.md·지시사항.md)를 앱이 fetch해서 사용자 저장소에 바로 커밋하는 방식으로 구현 — 결과물은 동일하고, 나중에 진짜 템플릿 저장소로 바꿔도 이 파일들을 그대로 옮기면 된다.
- **저장소 이름은 영문 슬러그 자동 생성(`office-xxxxxx`), 팀 이름(한글 가능)은 별도 필드로 분리.** GitHub 저장소 이름의 유니코드 지원 범위가 불확실해 리스크를 피했다. 목업(`design/pixel-journey/TeamSetup.dc.html`)의 "하윤의-사무실" 같은 한글 슬러그는 채택하지 않음.
