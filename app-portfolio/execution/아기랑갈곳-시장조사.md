# "아기랑 갈곳" 서비스화 시장조사 보고서

작성일: 2026-08-18
대상: `baby-place-registry/` (실사용 중인 개인 프로토타입, 서비스화 여부 검토)

전제: 회장이 이미 "지금 상태로는 서비스로 내놓을 정도는 아니다"라고 판단한 상태. 이 보고서는 그 판단을 시장 근거로 뒷받침하고, 서비스화한다면 무엇이 필요한지 우선순위를 매긴다. **WebSearch로 실제 검색해 확인한 사실(출처 표시)과 내 판단(추정)을 구분해서 썼다.**

---

## 0. 지금 앱이 실제로 하는 것 (코드 기준 재확인)

`baby-place-registry/index.html`(실사용 배포본, `.jsx`는 죽은 옛 버전)을 직접 읽어 확인:

- 링크/텍스트 붙여넣기 → 링크인지 텍스트인지 자동 판별(정규식으로 URL 여부만 판별) → 유형(놀곳/먹을곳/카페/기타)·대상(아기전용/전연령/어른동반)은 **사람이 칩을 눌러 수동 선택**. 즉 "자동 분류"는 **소스 판별만 자동**이고 카테고리 분류 자체는 자동이 아니다 — 회장/사용자에게 이 앱을 설명할 때 이 부분은 과장하지 않는 게 맞다.
  - 검증: `guessName()`은 URL이면 호스트명만 뽑아 이름을 추정, 텍스트면 그대로 이름으로 씀. AI/휴리스틱 기반 카테고리 자동판별 로직은 없음.
- 카카오맵 SDK 연동(장소 검색, 지도 핀), Firebase Firestore 동기화(실패 시 localStorage 폴백), 태그·즐겨찾기·평점·정렬(거리순 포함)·"공유" 버튼(URL 복사 — 단, 코드 내 안내문에 "지금은 기기별로 따로 저장돼서 실시간 공유는 안 됨"이라고 명시돼 있어 실질적 다인 동기화 기능은 아님).
- 즉 현재 앱은 **개인용 장소 스크랩북 + 지도 핀**이며, 표에서 회장이 매일 실사용 중이라고 기록된 상태다(`app-portfolio/README.md`).

이 특성(자동분류는 사실상 없음, 공유는 반쪽짜리, 개인 저장 중심)을 염두에 두고 아래 시장조사를 읽어야 한다.

### 1-2. 인접 경쟁 — 대형 플랫폼의 내장 기능 (가장 위협적인 "보이지 않는 경쟁자")

- **카카오맵 "테마지도"**: 주변탭 + 테마별 장소 큐레이션 기능이 이미 내장돼 있다.
- **판단(추정 아님, 검색으로 확인된 사실)**: "링크 붙여넣기 → 저장 → 태그/색상 분류 → 지도 핀 → 공유 링크"라는 이 앱의 핵심 플로우는, **네이버지도/카카오맵에 이미 무료로 내장된 기능과 기능적으로 거의 겹친다.** 게다가 이 앱이 지금 쓰는 지도 SDK 자체가 카카오맵이라, "카카오맵 위에 손으로 만든 미니 레이어"에 가깝다 — 부모 입장에서는 이미 깔려있는 지도 앱에서 리스트 만들면 되는데 별도 앱을 설치할 이유가 약하다.

## 2. 이 앱이 지금 상태로 서비스가 되기 어려운 이유

시장 근거 기반으로 정리하면:

1. **"자동 분류"라는 핵심 셀링포인트가 실제로는 없다.** 카테고리·대상은 사용자가 직접 칩을 눌러 고르는 수동 입력이고, 자동화되는 부분은 "URL이냐 텍스트냐" 판별뿐이다. 반면 경쟁 서비스들은 이미 존재하는 전국 DB에서 "검색·발견"을 제공해 사용자가 아무것도 입력하지 않아도 된다 — 방향 자체가 다르고, 지금 앱의 강점으로 내세우기엔 구현이 안 맞다.
2. **핵심 기능이 대형 플랫폼(네이버지도/카카오맵)에 무료로 이미 내장돼 있다.** "리스트 저장 + 분류 + 공유 링크"는 네이버지도가 이미 제공하는 기능이라, 별도 앱 설치를 유도할 차별화 요인이 약하다. 게다가 지금 이 앱은 카카오맵 SDK 위에서 동작해 "카카오맵의 부분집합"처럼 보일 위험이 있다.
3. **"공유"가 이름만 있고 실질이 없다.** 코드 내 안내 문구가 스스로 "기기별로 따로 저장돼 실시간 공유는 안 됨"이라 밝히고 있다. 반면 이미 존재하는 대안(맘카페 게시글, 인스타 컬렉션, 네이버지도 공개 리스트)은 전부 진짜 공유·발견이 된다. 개인용 도구로 남기엔 괜찮지만, "다른 부모와 공유"라는 방향으로 서비스화하려면 여기부터 다시 만들어야 한다.
4. **투자받은 직접 경쟁자가 이미 100만+ 회원 규모로 존재한다(애기야가자).** 이들은 이미 O2O 예약·커머스로 수익모델까지 갖췄고, VC 자금으로 DB(2만+ 장소) 구축을 마쳤다. 신규 앱이 "전국 장소 DB + 발견" 경쟁으로 들어가는 것은 승산이 매우 낮다 — 그 경쟁을 안 해야 한다는 뜻이지, 이 카테고리 자체가 안 된다는 뜻은 아니다(아래 3장 참고).
5. **보안/개인정보 이슈가 아직 정리 안 됨(서비스화 전 필수 선결 과제).** `app-portfolio/README.md`에 이미 기록돼 있듯 Firestore 보안규칙 확인이 안 된 상태, 정렬 기준점으로 실제 자택 주소가 하드코딩돼 있음. 지금은 개인용이라 문제가 작지만, 외부 사용자가 붙는 순간 데이터 유출·비용 폭탄(Firestore 요금) 리스크로 커진다.

**결론적으로: "지금 상태(=개인 큐레이션 도구, 자동분류 없음, 공유 반쪽)로 그대로 외부에 낸다"는 시장에서 자리가 없다.** 이미 존재하는 무료 대안(네이버지도 저장 리스트)과 겹치고, 유료 경쟁자(애기야가자 등)와는 체급 차이가 크다.

## 3. 서비스화하려면 필요한 것 (우선순위)

지금 앱의 실제 강점은 "빠른 개인 기록 + 카카오맵 핀 + 태그"다. 이 강점을 살리는 방향으로 좁혀야 승산이 생긴다.

1. **(최우선) 니치를 좁혀서 "전국 DB 경쟁"을 피한다.** 후보:
   - **우천시/실내 전용**: "비 오는 날 갈 곳"만 다루는 초점형 앱. 애기야가자·맘맘은 카테고리가 넓어 이 축으로 좁힌 서비스가 없음을 검색으로 확인(직접 대응 서비스 미발견) — 계절/날씨 검색 트리거가 명확해 공유 시 바이럴이 쉬움.
   - **신생아~돌 전(0~12개월) 전용**: "수유실·기저귀교환대·유모차 동선" 같은 이 연령대 특유의 정보 밀도가 높은 좁은 문제. 엄마의지도가 연령대 추천을 이미 하지만 "신생아 전용"으로 더 좁힌 서비스는 미발견.
   - **특정 지역(예: 회장 거주 지역) 한정**: 맘카페가 이미 강력한 지역 채널이라 정면 승부는 불리하지만, "맘카페 게시글은 검색이 안 되고 정리가 안 된다"는 불편을 대신 정리해주는 **맘카페 보완재** 포지션은 가능성 있음(아래 4번과 연결).
2. **"내가 기록한 걸 남들과 공유"가 아니라 "남들이 이미 올린 걸 내가 빠르게 저장"으로 방향을 조정한다.** 지금 핵심 입력값이 "링크 붙여넣기"인데, 이 링크의 실제 출처는 인스타/맘카페/블로그 게시글일 가능성이 높다. 그렇다면 승부처는 "저장을 자동화하는 것"(진짜 자동 분류: 링크를 열어 제목·이미지·본문에서 실제로 카테고리를 추정하는 것) — 지금은 이름조차 호스트명만 뽑는 수준이라 여기부터 실제 자동화가 필요하다.
3. **공유를 "링크 복사" 수준이 아니라 진짜 협업(부부 공동 리스트, 같은 어린이집 학부모끼리 리스트 공유)으로 만든다.** Firebase가 이미 붙어있어 기술적 장벽은 낮음 — 이미 회장이 실사용 중인 인프라를 그대로 확장하면 됨.
4. **맘카페 보완재 포지션**: 맘카페/인스타에서 흩어져 소비되는 정보를 "검색·정리 가능한 개인 아카이브"로 재구성해주는 도구로 포지셔닝. 맘카페와 경쟁하지 않고 "맘카페 글 저장용 도구"로 얹혀가는 방향 — 저비용 검증 가능(맘카페에 소개 글 하나 올려 반응 확인).
5. **수익모델은 서비스 방향이 정해진 뒤에 검토.** (4장 참고)

**우선순위 근거**: 1번(니치 좁히기)이 없으면 나머지가 다 의미 없다 — 이미 100만 회원급 경쟁자가 있는 시장에서 "더 나은 범용 장소 앱"으로는 이길 수 없다는 게 이번 조사의 핵심 발견이다.

## 4. 비즈니스 모델 후보 (조사 결과 + 판단)

- **광고**: 애기야가자·맘맘 등 대형 경쟁자가 이미 광고 기반(추정 — 앱스토어 개인정보 처리방침에 광고식별자 수집 명시, 정확한 매출 공개 자료는 검색으로 못 찾음)이라, 신규 소규모 앱이 광고로 유의미한 수익을 내기는 어려움. 트래픽 규모가 절대적으로 작아 CPM 기반 광고는 사실상 용돈 수준.
- **제휴 커미션(키즈카페 예약 등 O2O)**: 애기야가자가 이미 Vertical-Commerce 모델로 자리잡음(예약 연동). 이 모델은 가맹 계약·정산 인프라가 필요해 1인 사이드프로젝트가 단기간에 따라가기 어려움 — 낮은 우선순위.
- **유료 구독**: 검색으로 한국 육아 앱 카테고리의 구체적 구독 전환율 데이터는 찾지 못함(일반적으로 한국이 구독 결제 전환율 상위권 국가군에 속한다는 정황 자료만 확인 — [출처](https://medium.com/delightroom/%EA%B5%AD%EA%B0%80%EB%B3%84-%EA%B5%AC%EB%8F%85-%EC%A0%84%ED%99%98%EC%9C%A8-%EC%B0%A8%EC%9D%B4-5f0f300fdbfb)). 육아 카테고리 자체의 결제 전환율을 뒷받침하는 자료는 못 찾았으므로 **이 부분은 판단 보류**로 남긴다 — 단정하지 않음.
  - 판단(추정): 무료 대안(네이버지도, 맘카페)이 이미 충분한 상황에서, 이 앱이 유료 구독으로 전환시킬 만한 "돈 낼 이유"를 만들려면 3장의 니치 좁히기 + 진짜 자동화가 선행돼야 함. 지금 상태로는 유료 전환 논의 자체가 시기상조.
- **B2B(키즈카페/유아시설 대상 리스팅 광고)**: 애기야가자 규모가 이미 이 시장을 상당 부분 점유. 신규 진입 시 영업 리소스가 필요해 회장 리소스 제약(개입 최소화, 반복 오프라인 대면 배제 원칙)과 충돌 — 현재 원칙상 부적합.

**종합 판단**: 지금 조사한 범위에서는 뚜렷하게 유리한 수익모델이 보이지 않는다. 니치가 좁혀지고 실사용자 반응이 검증되기 전까지 수익모델 논의는 이르다.

## 5. 결론 — 서비스화 권고

**지금 상태로 정식 서비스화(공개 배포)를 추진할 가치는 낮다.** 이유는 회장의 기존 판단과 일치한다:

- 핵심 기능("자동 분류")이 실제로는 구현돼 있지 않고,
- 나머지 기능(저장 리스트 + 분류 + 지도 핀 + 공유 링크)은 네이버지도/카카오맵에 이미 무료로 내장돼 있으며,
- 직접 경쟁 카테고리(전국 장소 발견 앱)는 이미 VC 투자를 받은 100만+ 회원급 플레이어(애기야가자)가 장악하고 있고,
- 비공식 채널(맘카페·인스타)의 정보 밀도와 신뢰도가 압도적으로 높다.

**그럼에도 "완전히 접어야 한다"는 결론은 아니다.** 지금 앱은 회장이 실사용 중일 만큼 개인 도구로서는 이미 검증됐다 — 문제는 "이 형태 그대로 넓히면 시장이 없다"는 것이지 "이 아이디어 자체가 가치가 없다"는 게 아니다.

**권고하는 다음 스텝(좁은 니치부터, 무자본 검증 원칙에 맞게)**:

1. 지금은 **개인용으로 유지**하고 서비스화를 보류한다 — 이번 조사로 회장의 기존 판단이 뒷받침됨.
2. 만약 서비스화를 재검토한다면, 3장 1번의 니치 중 **"우천시/실내 전용" 또는 "신생아~돌 전 전용"**처럼 검색으로 직접 경쟁을 못 찾은 좁은 축부터 시작하는 것이 맞다. 두 축 다 기존 코드(카카오맵+Firebase)를 그대로 재사용할 수 있어 추가 개발비가 거의 들지 않는다(`candidates.md`의 N5 아이디어와 궤를 같이함).
3. 그 전에 반드시 "진짜 자동 분류"(링크를 열어 제목/본문에서 카테고리 추정) 하나만이라도 먼저 구현해, 지금 앱 소개 문구("자동 분류")와 실제 동작의 간극부터 없앤다 — 이건 니치 선택과 무관하게 언제든 할 수 있는 저비용 개선.
4. Firestore 보안규칙 확인 + 자택 주소 하드코딩 제거는 니치를 정하는 것과 별개로, 외부 사용자가 한 명이라도 붙기 전에 반드시 선행해야 한다.
