### 무료 맛보기 여러 종 + 유료 뉴스레터 대량생산 (2026-08-18, 회장 제안)

회장 아이디어: "향후에는 맛보기용 무료레터도 몇 종류 넣고 유료레터도 대량 생산하면 어떨까." N1이
단일 유료 뉴스레터 하나에 올인하는 구조인데, 대신 **여러 개의 좁은 니치 무료 뉴스레터("맛보기")를
동시에 굴려서 각각 소규모 오디언스를 모으고, 그중 반응이 검증된 것만 유료 라인으로 승격**하는
포트폴리오 방식.

**은우 1차 판단 — 방향에 동의, 다음 이유로 이 회사에 잘 맞는다:**
- **A1(니치템플릿) 대량생산 방식이 이미 검증된 패턴** — 하루 10건 콘텐츠 생산 루틴이 니치템플릿에서
  실제로 돌고 있음(`niche-templates/README.md` 운영원칙 8번). 뉴스레터도 콘텐츠 생산 자체는 AI가
  전담 가능한 영역이라 같은 방식으로 확장 가능.
- **리스크 분산** — N1 하나에 올인하는 것보다, 여러 니치를 동시에 던져서 어느 게 뜨는지 시장이
  골라주게 하는 게 "무자본 검증 우선" 원칙에 더 맞음.
- **회장 개입 최소화 조건 충족** — 무료 뉴스레터는 결제·PG 연동이 없어 계정 승인 관문도 거의 없음
  (스티비 무료 플랜에서 주소록만 여러 개 만들면 됨, 계정 추가 가입 불필요).

**남은 질문(다음 라운드에서 정리)**:
1. 니치 후보를 몇 개로 시작할지.
2. "맛보기"의 정의 — N1처럼 별도 콘셉트인지, 아니면 N1 콘텐츠의 발췌/편집판인지.
3. 유료 전환 기준(구독자 수·오픈율 등 구체 수치)을 세워야 "검증됐다"를 판단할 수 있음 — 아직
   미정.

**정정(2026-08-18)**: 위 1번에서 언급했던 나다컴퍼니9(다연) E2는 실제로는 별도 콘텐츠 기획 없이
"특정 버티컬 큐레이션" 정도의 일반적 컨셉만 있었고, **2026-08-12에 이미 A5/N1로 전량 흡수돼
정리 끝난 상태**라 재사용할 구체 자료가 없다 — 아래 니치 후보는 E2와 무관하게 새로 리스트업.

## Beehiiv 자동화 범위 조사 (2026-08-12, 은우, 공식 문서 기준)

### API 지원 여부
- Beehiiv는 Publications/Posts/Subscriptions 등 REST API를 공식 제공한다 — [개발자 문서](https://developers.beehiiv.com/).
- **API 키는 발행물(Publication) 설정에서 발급하며, 발급 전 Stripe Identity Verification(본인확인)이 필요하다**는 서포트 문서가 있음 — 이건 회장이 실물 신분증 인증을 해야 하는 단계일 가능성이 높다(나다컴퍼니3 실거래 KYC와 유사한 성격). 실제 가입 시점에 재확인 필요.
- **⚠️ 상충 정보 발견 — Create Post(발행) API의 플랜 조건이 출처마다 다르다.**
  - 공식 API 레퍼런스(`developers.beehiiv.com/api-reference/posts/create`)엔 "이 기능은 베타이며 **Enterprise 사용자 전용**"이라고 명시돼 있음.
  - 반면 공식 가격 페이지(`beehiiv.com/pricing`)엔 "Launch(무료)·Scale 플랜도 API 접근 가능(Send API 제외), Max부터 Send API 포함"이라고 돼 있어 **Create Post는 Max 플랜에서도 가능한 것처럼 보임.**
  - 즉 "발행 자동화(포스트를 API로 만들고 발송)"가 정확히 어느 플랜부터 되는지 문서만으로는 확정할 수 없다. **무료 계정을 실제로 만들어 API 키 발급 화면·플랜별 안내를 직접 확인하기 전까진 "완전자동 발행"을 전제로 설계하면 안 됨.**

### 결제·정산 방식
- **유료 구독은 Beehiiv 자체 결제가 아니라 사용자 개인 Stripe 계정을 연결하는 방식** — 스티비(자체 PG 내장)와 다르게, Beehiiv는 구독자 결제·매출 처리를 전적으로 연결된 Stripe 계정이 담당한다.
- 정산은 **Stripe 표준 payout 스케줄로 연결된 은행계좌에 자동 입금** — "포인트/캐시로 쌓인 뒤 별도 출금 신청" 구조가 아니라서 [원칙 5](../niche-templates/README.md#회장-리소스-제약-2026-08-05-확정-모든-안건에-항상-적용)(현금 계좌직접입금 우선)에 잘 맞는다. Stibee와 동급이거나 오히려 Stripe라 국제표준이라는 장점.
- **Beehiiv는 유료구독 매출에 대해 0% 수수료**를 공식 표방(플랫폼 자체 수수료 없음, Stripe 결제수수료만 발생) — 스티비와 유사한 구조.
- Stripe는 개인 자격(사업자등록 없이) 연결 가능 — Gumroad 등 기존에 이미 쓰는 개인 판매 채널과 동일한 성격이라 "사업자등록 불가" 제약에 걸리지 않는다.

### 개인 가입 가능 여부
- 무료 플랜(Launch)은 신용카드 없이 이메일/구글 가입 + 휴대폰 인증만으로 개설 가능, 사업자 정보 요구 없음.
- **다만 유료구독(수익화) 기능은 무료 플랜엔 없고 Scale 플랜부터 활성화된다.** Scale은 **$43/월(연간 결제 기준, 약 5.8만원/월)** — 스티비(플랫폼 자체는 무료, 결제 건당 PG 수수료만 발생)와 달리 **매출 발생 여부와 무관하게 매달 고정비가 나가는 구조**라는 게 핵심 차이.

### 요약 — 스티비(A5) vs Beehiiv 비교

| 항목 | 스티비(A5, 기존 검증 완료) | Beehiiv |
|---|---|---|
| 플랫폼 이용료 | 무료(결제 건당 PG 수수료만) | **무료 구간은 유료구독 불가 — 활성화하려면 $43/월 고정비** |
| 결제 처리 | 스티비 내장 PG | 개인 Stripe 계정 연결 |
| 정산 | 스티비 → 계좌(신고 절차 별도 확인됨, KEEP 판정 완료) | Stripe 표준 payout → 계좌 직접입금(자동) |
| 발행 자동화(API) | 미확인(스티비는 애초에 API 자동화 대상으로 조사한 적 없음) | 문서 상충 — Max 이상 확실, Create Post는 Enterprise 한정이라는 문서도 있어 **재확인 필요** |
| 가입 난이도 | 이메일 가입(회장 액션 1회, 아직 미완료) | 무료 가입은 동일하게 쉬움. **유료 구독을 켜려면 결제(Scale 구독) 필요 → 회장 승인 사안** |
| 해외 크리에이터 생태계 접근성(Boost 등) | 국내 중심 | 해외 크리에이터 이코노미 결합(Beehiiv Boost 크로스프로모션 등) — 무자본 홍보 채널로 유리 |

**결론(은우 판단)**: Beehiiv가 "완전 자동화·해외 생태계" 관점에선 매력적이지만, **유료구독을 켜는 순간 스티비에는 없던 월 $43 고정비가 생긴다**는 게 A5→Beehiiv 단순 이관 판단에서 가장 중요한 새 변수다. 무료 플랜으로 콘텐츠·구독자 기반을 먼저 쌓고, 유료화 시점(=Scale 결제)만 회장 승인을 받는 식으로 리스크를 나눌 수 있다.

### ⚠️ 정정 — 스티비도 무료 플랜에서 유료구독 안 됨 (2026-08-17, 은우, 실제 로그인해서 확인)

위 표의 "스티비: 무료(결제 건당 PG 수수료만)"는 **문서 조사만으로 낸 결론이었고, 실제로 로그인해서 확인해보니 틀렸다.** 회장이 만들어준 계정으로 실제 로그인 → 주소록 생성 화면까지 들어가 확인:

- **"유료 구독 주소록" 만들기를 누르면 즉시 업그레이드 안내 모달만 뜨고, 무료(스타터) 플랜에서 그냥 진행하는 경로가 없다** — "닫기"를 눌러도 취소만 되고 실제로 생성되지 않음(재확인 완료).
- 실제 요금제 페이지(로그인 후 "업그레이드 하기") 확인 결과, **"유료 구독" 기능은 스탠다드 플랜(월 8,900원, 부가세 포함)부터 포함**. 스타터(무료) 플랜 기능 목록엔 유료 구독이 아예 없음.
- 즉 스티비도 Beehiiv·Kit·MailerLite와 마찬가지로 **"유료구독 자체가 유료 플랫폼 업그레이드 없인 안 되는" 구조** — 다만 금액은 훨씬 작다(월 8,900원 vs Beehiiv $43).

**비교표·결론 갱신 필요**: "지금 당장 무료로 유료구독까지 가능한 곳은 스티비뿐"이라는 기존 결론은 폐기. 정확한 현재 상태는 [`README.md`](README.md)에 반영.

## 뉴스레터 발행 플랫폼 폭넓은 비교 (2026-08-12, 회장 지시 — "최대한 많이 점검")

회장이 **"유료 플랫폼을 지금은 쓰고 싶지 않다"**는 제약을 명시해서, Beehiiv 외에 무료로 시작 가능한 대안까지 넓게 조사했다. 기준은 4가지: (1) 플랫폼 자체 이용료가 무료/최소인가, (2) 유료구독 기능을 켤 때 추가 고정비가 있는가, (3) 발행·구독자 관리를 API로 자동화할 수 있는가, (4) 정산이 계좌 직접입금인가.

### 조사 결론 (은우)
- **"지금 당장 유료 플랫폼을 쓰지 않는다"는 기준만 보면 스티비·Substack·Ghost(셀프호스팅) 세 곳이 0원으로 유료구독까지 가능**하다. 이 중:
  - **스티비**: 이미 콘텐츠·검증 끝난 A5 자산 그대로 재사용 가능, API도 있어 자동화 원칙에도 부합 — 회장이 제시한 "현재안"과 정확히 일치.
  - **Substack**: 오디언스 발견 기능은 매력적이지만 **공식 발행 API가 없어 나다그룹의 핵심 필터("플랫폼이 자동화를 공식 지원하는가")를 통과하지 못함** — 원칙상 Tier A 자격 미달.
  - **Ghost 셀프호스팅**: 수수료 0%·API 최강이지만 서버 운영이라는 새로운 회장 개입 지점이 생겨, 지금 규모(니치 뉴스레터 1개)에는 과한 선택일 수 있음. 구독자·매출이 커지면 재검토 후보로 파킹.
- **Beehiiv·Kit·MailerLite는 모두 유료구독을 켜는 순간 월 $12~43 고정비**가 발생 — 회장이 "유료 플랫폼은 지금 쓰고 싶지 않다"고 한 것과 정면으로 배치됨.
- **Buttondown**은 예외적으로 눈여겨볼 만하다 — 유료구독 애드온이 $9/월로 다른 유료 플랫폼보다 훨씬 싸고, 무료 단계에서도 API를 전부 쓸 수 있어 나중에 해외/개발자 오디언스 대상 2호 라인을 열 때 후보로 남겨둘 만함(지금 결제는 원하지 않으니 즉시 채택 대상은 아님).

**은우 판단**: 회장의 "현재안(스티비부터)"이 이번 폭넓은 비교에서도 가장 타당하다고 나옵니다 — 무료·검증완료·API자동화 3박자가 맞는 유일한 조합입니다. Beehiiv는 나다컴퍼니10 신설 때 지정된 플랫폼이지만, 지금 시점(무자본 우선)에는 스티비 대비 이점(해외 생태계)보다 월 $43 고정비라는 단점이 더 크다고 보입니다.
