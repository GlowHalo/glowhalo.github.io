# E1 — 웨어러블 헬스데이터 AI 웰니스 인사이트 리포트 (실행 로그)

담당: 다연(나다컴퍼니9). 후보 선정 근거는 [`../candidates.md`](../candidates.md) E1 참고. 이 문서부터는 리서치가 아니라 **실행**.

## 브랜드 — "리듬노트 (RhythmNote)" (2026-08-12 잠정 확정)

- 오라링/애플워치/갤럭시워치/가민 등에서 나온 수면·활동·심박변이(HRV) 데이터를 업로드하면, **의료 진단이 아닌 "자기이해용" 패턴 해석 리포트**를 만들어주는 상품.
- 이름은 잠정(assessment-products Reflect Lab처럼 정식 상표조사는 매출 발생 후 재검토). 로고/비주얼 아이덴티티는 아직 없음 — 텍스트 브랜딩으로 시작.
- **"진단/치료/의학적 조언 아님"을 모든 접점(랜딩페이지, 리포트 표지, 이메일)에 명시** — 헬스케어 분과 조사에서 지적된 유일한 리스크가 문구 관리였기 때문에 가장 먼저 고정.

## 상품 구조

1. 고객이 랜딩페이지에서 데이터 업로드(이메일 export 파일 또는 앱 스크린샷) + 이메일 주소 입력
2. 결제(아래 "결제 채널" 참고)
3. 다연(Claude)이 배치로 데이터를 분석해 리포트 마크다운 작성 → PDF 렌더링
4. 이메일로 PDF 전달 (24~48시간 이내 목표)

**중요한 설계 결정 — "실시간 자동화"가 아니라 "배치 처리"다.** 처음엔 백엔드가 별도 LLM API(Anthropic/Gemini)를 호출해 즉시 리포트를 생성하는 완전 자동 파이프라인을 그렸는데, 다시 보니 `birkman-automation`이 이미 이 패턴(Claude가 세션에서 직접 분석·PDF 생성·Resend 발송)으로 돌아가고 있었다. 그 패턴을 그대로 재사용하면:
- 별도 LLM API 키(신규 계정/과금)가 필요 없음 — 분석은 다연(나) 세션이 저녁 시간대에 직접 수행
- 품질 관리가 쉬움 — 자동 생성물을 무검수로 발송하지 않음(헬스데이터라 오해석 리스크가 있어 특히 중요)
- "겸업창업자+AI" 리소스 제약(저녁 1~2시간 집중작업)과 정확히 맞음

## 기술 아키텍처 (2026-08-12 구축)

```
[랜딩페이지 rhythmnote/index.html]
   └→ 업로드 폼(이메일+파일) → POST → [Cloudflare Worker rhythmnote-intake]
                                            ├→ R2에 원본 파일 저장
                                            ├→ KV에 제출 레코드(status: received) 저장
                                            └→ Resend로 다연 앞 알림메일 발송
   └→ Gumroad 결제 링크(신규 발행은 회장 확인 후)

[배치 처리 — 다연이 저녁에 실행]
   scripts/list-submissions.mjs  → KV에서 status=received 목록 조회
   (다연이 R2 원본을 읽고 직접 분석 → 마크다운 리포트 작성)
   scripts/render-report-pdf.mjs → 마크다운 → 스타일 PDF (birkman 패턴 재사용, Playwright)
   scripts/send-report.mjs       → Resend로 고객 이메일 발송 → KV status: delivered
```

배포 상태는 아래 "진행 상황" 참고. 코드는 저장소 루트 `rhythmnote/`.

## 결제 채널 — 무료 베타로 먼저 검증, 결제는 그다음

새 결제 계정(Stripe/토스페이먼츠)을 새로 만들 필요 없음 — 나중에 유료 전환할 때도 **이미 연동 완료된 Gumroad**(A1/A2가 쓰는 채널, API 토큰 확보됨)를 재사용하면 된다.

**2026-08-12 실행 결정 — 지금은 결제 자체를 미루고 "무료 베타"로 파이프라인부터 실제로 돌려본다.** 이유:
1. E1은 실제 건강데이터를 다루는 나다컴퍼니9 첫 상품이라 assessment-products(Reflect Lab)가 PII를 다룰 때처럼 초기엔 보수적으로 시작하는 게 맞음
2. niche-templates 운영원칙 2번의 "회장 승인 없이 발행 가능" 예외는 현재 A1 Gumroad 라인·A2 PromptDeck에 한정돼 있어, biz-scouting가 곧바로 유료 발행하려면 회장 확인이 어차피 필요함
3. 그렇다고 손 놓고 기다리기보다, **결제 없이도 검증 가능한 부분(업로드 파이프라인 동작, 실제 데이터로 리포트 품질)을 먼저 확인**하는 게 효율적 — "진짜 팔기 시작" 결정을 회장이 내릴 때 이미 파이프라인이 검증된 상태로 갈 수 있음

랜딩페이지는 무료 업로드 폼으로 이미 라이브(아래 "진행 상황" 참고). 유료 전환(Gumroad 발행)만 회장 확인 후 진행.

## 막힌 지점 — 이메일 발송 (assessment-products와 동일한 그룹 공통 이슈) → 2026-08-17 해소 진행 중

`resend_api_key`는 이미 금고에 있지만, **커스텀 도메인 인증 전엔 Resend가 발신자 본인 이메일(`tossneon0@gmail.com`)에만 발송을 허용**한다(`.claude/rules/birkman.md` 참고 — assessment-products가 먼저 겪은 문제). 이건 E1만의 문제가 아니라 **나다그룹 전체가 공유하는 인프라 블로커**였다.

**2026-08-17 진행 상황(HQ 세션이 처리, `hq/가입대기.md` 확인)**: 회장이 그룹 공용 발신 도메인(`nadagroup.org`)을 이미 구매했고, Cloudflare DNS 편집 권한도 받아 DKIM/SPF/MX 레코드 등록 + Resend 인증 요청까지 끝난 상태 — 현재 `pending`(DNS 전파 대기), 완료되면 assessment-products·biz-scouting 둘 다 동시에 풀린다. **더 이상 회장 확인 대기 항목이 아니다** — 다음 세션에서 Resend 대시보드/API로 `verified` 전환 여부만 재확인하면 됨. 전환되면 `rhythmnote@nadagroup.org` 같은 발신주소로 실제 고객 발송 시작 가능.
