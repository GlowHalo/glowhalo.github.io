# 상품 실제 콘텐츠 초안 — 프롬프트 세트 & 데모 (품질 검증용)

> 회장 질문("SaaS창업자 수준까지 퀄리티가 되냐")에 대한 답: 스펙만으로는 안 됩니다. 그래서 "다음 단계"로 미루지 않고 지금 실제 콘텐츠를 써봤습니다. 이 프롬프트들은 지어낸 게 아니라 **이 회사를 실제로 운영하면서 이미 3라운드 넘게 검증한 것들을 그대로 뽑아낸 것**입니다 — 이게 우리의 진짜 차별점입니다.

## 프롬프트 세트 (역할별 5개, 실제 사용 가능한 완성형)

### 🎯 Strategy Exec — 5 prompts

**1. Blank-Slate Opportunity Scan**
```
You are my Strategy Exec. Do NOT reference [existing product/project] — evaluate this
completely from scratch, as if it didn't exist.

Constraints (do not violate):
- Initial validation budget: [$X], zero-cost ideas strongly preferred
- Time I can invest: [Y hours/week], mostly [evenings/weekends]
- [Any hard constraint: e.g. "no LLC yet", "day job conflicts", "solo, no team"]

Task: Propose 3 opportunities that fit these constraints. For each: one-line concept,
why now (trend evidence, not vibes), target customer, a concrete validation test
that fits the budget, and the specific number/signal that would prove or kill it.
End with your top pick and why.
```

**2. Steelman the Case Against This** *(anti-sycophancy — the core mechanism)*
```
I'm about to commit to: [idea/decision]. Do not validate me. Your job is to build
the strongest possible case that this is a mistake — pretend you're a skeptical
investor who has seen 200 pitches like this fail. Cite the specific failure mode,
not generic risk language ("competition exists" is not enough — name who, and why
they'd beat me specifically).
```

**3. Positioning Check (STP)**
```
Here's my product: [description]. Here are 3 competitors I found: [list, with prices].
Segment this market into 2-3 groups. Tell me honestly which segment I'm strong
enough to win, which I'd lose, and write one positioning sentence that only makes
sense for the segment I should target.
```

**4. Pricing Sanity Check**
```
I'm about to price [product] at [$X]. Here's what comparable products charge: [list].
Tell me if I'm anchoring too low (signals "cheap/low-trust") or too high (signals
"overpriced for an unproven seller"), and give me the specific number range with reasoning.
```

**5. Kill/Keep Decision**
```
It's been [timeframe] since I started [initiative]. Here's what happened: [data/results].
I need a KEEP or KILL verdict, not "it depends." State the one number that would have
made you say KEEP, and whether we hit it.
```

### ⚙️ Tech Exec — 5 prompts

**1. Zero-Touch Audit** *(our actual methodology from this session)*
```
Can [business idea] run with ZERO ongoing involvement from me after initial setup —
not "low effort," literally zero? Check each of: content creation, publishing/delivery,
payment collection, customer inquiries. For each, say KEEP (truly automatable) or
PASS (requires recurring human judgment) with the specific mechanism, not a guess.
```

**2. Platform-Native Automation Check**
```
Does [platform, e.g. "Etsy", "YouTube", "Naver Webnovel"] officially support automation
(a public API, an official CLI) for [action], or would I be scripting around a UI meant
for humans (ToS risk, ban risk)? This distinction is the single biggest predictor of
whether "automated" actually survives contact with the platform.
```

**3. Build vs. Buy Feasibility**
```
I want to build [feature/product]. Given my stack is [languages/tools I know], estimate:
realistic build time, the one part most likely to be harder than it looks, and whether
an off-the-shelf tool already solves 80% of this for less effort.
```

**4. MVP Scope Cutter**
```
Here's my full plan for [product]: [description]. Cut it down to the smallest version
that tests the ONE riskiest assumption — not the smallest version that's technically
impressive. Name the assumption and why testing it first de-risks everything else.
```

**5. Recurring-Cost Audit**
```
List every cost in [plan] that recurs (subscriptions, renewal fees, API usage-based
costs) vs. one-time costs. Flag anything that scales with success in a way that could
eat margin, and anything that's a fixed cost regardless of whether the business works.
```

### 📈 Growth Exec — 5 prompts

**1. Channel-Fit Scan**
```
For [product], does it live on a platform with its own built-in discovery (marketplace
search, app store, algorithm-fed feed) — or do I need to bring my own audience with
zero ad budget? Be specific about which channels apply and which don't; "post on social
media" is not specific enough.
```

**2. Persona Sharpening**
```
My target customer is "[vague description, e.g. 'solo founders']." That's too broad.
Narrow it to a specific, findable group (a subreddit, a community, a job title with a
specific pain point) and tell me why that narrower group converts better than the
broad one.
```

**3. Cold-Start Distribution Plan**
```
I have $[X] and [Y hours/week]. Give me a concrete distribution plan for the first
[N] customers — name actual channels/communities, not "build a following." Rank by
speed-to-first-signal, not by long-term potential.
```

**4. Landing Page Structure**
```
Draft a 10-section landing page outline for [product] targeting [persona], following:
hook → problem → feature list → proof (screenshot/demo) → how-it-works → comparison
table vs named competitors → social proof → FAQ (objections first) → price+urgency → CTA.
```

**5. Objection Pre-Empt**
```
List the top 5 reasons someone in [target persona] would talk themselves out of buying
[product], ranked by how often you'd expect to hear them. Turn each into one FAQ answer
that kills the objection in 2 sentences.
```

## 데모 콘텐츠 — 실제 예시 (빈 템플릿 공포 해소용)

### Board Minutes — Round 1 (example, pre-filled in the template)

**Date**: [demo] · **Round**: Blank-slate opportunity scan · **Attending**: Strategy, Tech, Growth (independent review)

> **Strategy**: "Local coffee roaster subscription box — pitched as 'discovery' but really solving 'I don't know which of the 40 local roasters near me are actually good.' Trend: specialty coffee spend is up, but subscription fatigue is real. Validation: pre-sell 10 boxes via a $0 landing page before buying any inventory. Kill signal: fewer than 5 pre-orders in 2 weeks = the curation angle isn't differentiated enough."
>
> **Tech**: "This is NOT zero-touch — sourcing, packing, and shipping are physical and recurring. If the founder has a day job, this fails the zero-touch test outright. Recommend testing the 'curation' value prop without the logistics first: sell a $5 PDF guide ranking the 40 roasters, see if anyone pays for the *opinion* before committing to the *box*."
>
> **Growth**: "No platform-native discovery for a new subscription box — you're bringing 100% of your own audience. Local Reddit/Facebook groups are free but slow. Recommend the Tech Exec's cheaper test (the PDF guide) specifically because it can ride existing 'best coffee in [city]' search traffic, which the box itself cannot."

**Sample Proposal** (auto-generated from the above): *"Recommend testing the $5 curation guide before the box. All three execs independently flagged the same risk (logistics vs. differentiation) from different angles — that convergence is the signal to trust."*

## 사장의 솔직한 자체 평가

- **강점**: 프롬프트가 일반적인 "너는 전문가야, 조언해줘"류가 아니라 우리가 실전에서 검증한 구체적 방법론(제로터치 감사, 채널적합성 스캔 등)을 그대로 담고 있어 밀도가 높습니다. "실제로 쓰는 걸 판다"는 스토리는 AgentOS 같은 경쟁상품이 흉내내기 어려운 진짜 차별점입니다.
- **아직 부족한 것**: (1) 실제 노션 페이지로 옮겨서 시각적으로 다듬는 작업이 안 됨 — 지금은 텍스트 스펙일 뿐. (2) 베타테스터에게 실제로 써보게 해서 "말이 되는지" 검증이 안 됨. (3) 영상 튜토리얼 없음.
- **다음 액션**: 이 프롬프트·데모를 실제 노션 페이지로 제작 → 회장님이나 베타테스터 1~2명에게 실제로 복제해서 써보게 하고 반응 확인 → 그 피드백으로 한 번 더 다듬은 뒤 업로드. "만들자마자 판다"가 아니라 "실사용 검증 한 번 거치고 판다"로 가겠습니다.
