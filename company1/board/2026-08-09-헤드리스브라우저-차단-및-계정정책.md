# 2026-08-09 — HQ에서 전달: 헤드리스 브라우저 차단 확정 + 계정 활용 정책 변경

> HQ(회장+Claude)가 나다그룹 대시보드 작업 중 발견해서 별도 세션까지 붙여 끝까지 검증한 내용. 정연·임원진이 앞으로 같은 문제로 헤매지 않도록 여기 요약해서 전달.

## 1. 헤드리스 브라우저 — 이 실행환경 전체에서 구조적으로 막혀있음 (조치 불가, 반복 시도 금지)

- 증상: Playwright/Chromium으로 외부 HTTPS 사이트를 열면(대상 무관 — `example.com`도 재현) `ERR_CONNECTION_RESET`.
- 원인: 인증서 신뢰 문제가 아니라, **Chromium의 TLS 접속 요청(ClientHello) 자체가 프록시/게이트웨이 단에서 지문(fingerprint) 기준으로 차단**되는 것으로 확인됨. `curl`은 정상.
- **"다른 세션/네트워크 정책이면 될 것"이라는 가설은 기각됨** — 더 넓은 네트워크 정책("Full") 세션에서도 동일 재현. 세션별 문제가 아니라 모든 세션이 공유하는 인프라 문제.
- 상세 재현·시도 기록: [`company1/execution/헤드리스브라우저-프록시-이슈.md`](../execution/헤드리스브라우저-프록시-이슈.md)
- **영향받는 것**: 로그인 세션이 필요한 실제 브라우저 자동화(카카오 이모티콘 스튜디오 제출, Gumroad 관리자 화면 조작 등). API로 되는 작업(대부분)은 무관하게 정상.
- **영향 안 받는 것**: `curl`/API 호출 전부, 정적 페이지 응답 검사(HTML 텍스트 레벨 확인)는 curl로 대체 가능.
- 이 이슈를 다시 마주치면: 위 문서의 "시도해본 것"을 반복하지 말고, 회장에게 보고 후 (a) 회장이 직접 확인/진행하거나 (b) Anthropic 지원 채널 리포트를 회장에게 제안한다.

## 2. 계정 로그인 정보 — 이제 API 키와 동일하게 취급 (2026-08-09, 회장 확정)

회장 지시: **"내가 제공하는 계정들은 다른 API 키들처럼 활용해서 직접 로그인하거나 설정을 조정하는 등 활용하면 된다."**

- 회장이 기존 계정(가입은 이미 끝난 계정)의 로그인 이메일/비밀번호를 주면, `cloudflare-api-vault`(tossneon-api-vault) 금고에 등록해두고 그 계정으로 **직접 로그인해서 설정 조정·확인을 사장(AI) 재량으로 진행**한다. 매번 "로그인해도 될까요" 물어보지 않는다.
- 예시로 이미 등록된 것: `gumroad_login_email` / `gumroad_login_password` (Gumroad 관리자 화면 — API로 안 되는 설정, 예: 환불정책 스위치 전환용).
- **여전히 회장만 할 수 있는 것**: 계정을 **처음 만드는 것**(신규 가입)과 **본인인증**. "이미 있는 계정을 넘겨받아 쓰는 것"과는 다른 얘기 — 이 구분은 CLAUDE.md 자율성과 확인 원칙에 명문화됨.
- **현재는 위 1번 이슈 때문에 실제 로그인 자동화 자체가 막혀있다** — 정책은 열렸지만 실행 수단(헤드리스 브라우저)이 없는 상태. 그 이슈가 풀리면 바로 이 정책대로 진행하면 된다.
