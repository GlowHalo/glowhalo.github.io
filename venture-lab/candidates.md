## 2026-08-19 — 실제 지도 기반 가상 소유권 마켓플레이스 (Earth2류)

- **요약**: 실제 세계지도를 필지로 나눠 팔고, 최초판매+되팔기 수수료로 수익을 내는 모델. Earth2·세컨드라이프에서 착안, "소유욕+독점 심리" 자극이 핵심 엔진. 재미가 아니라 시세차익 기대(비트코인 붐과 같은 맥락)가 진짜 동력이라는 게 회장 확인.
- **논의 경위**: 회장이 직접 제안. 논의 중 "연예인 되팔기"(같은 심리구조, 다른 리스크군 — 초상권/인격권) 아이디어도 나왔으나 별도 파킹.
- **리스크 체크 결과**:
  - 되팔기+시세차익 기대 구조는 증권성(투자계약) 논란 소지 — 실제로 Dapper Labs(NBA Top Shot)가 같은 구조로 투자자 집단소송 당해 $4M 합의 (SEC 아니라 유저가 직접 건 민사소송이라는 게 핵심 — [Charltons Quantum](https://charltonsquantum.com/dapper-labs-reaches-4-million-settlement-affirms-nba-top-shot-nfts-are-not-securities/)).
  - 가상화폐 결제는 한국 특금법상 가상자산사업자 신고(=사업자등록 필요) 문제와 충돌 → 배제, 달러 결제로 진행.
  - 지도 API(Google Maps/Mapbox) 이용약관 모두 "지도 자체의 재판매/재배포" 금지 조항은 있으나, "지도를 우리 자체 상품(소유권 claim)을 보여주는 시각화 UI로만 쓰는" 표준적 상업 임베드 패턴(부동산·여행 스타트업들이 흔히 쓰는 방식)은 이 금지에 해당하지 않는 것으로 보임 — 다만 최종 계약 전 확인 필요.
- **판단**: 아직 확정 아님, 논의 계속 진행 중.
  - **법인설립(미국 LLC)은 이번엔 보류** — 회장이 "사업자 없는 개인 자격으로 진행"을 확정. 법인화하면 책임 분리·Stripe 직접연동 등 이점이 컸지만, 상황이 바뀌면 다시 꺼내볼 "파킹된 옵션"으로 기록만 남김.
  - **예산은 완화** — 최초 30만원 원칙보다 높게, 수천 달러까지는 아닌 범위로 투자 가능(정확한 상한은 다음 논의에서 확정).
  - **유료 지도 서비스 사용은 허용**, 단 이번 사업 용도(소유권 claim 판매)에서 법적 리스크가 없는지 계약 전 재확인 필요.
- **다음 단계**: 자산을 꼭 "땅"으로 한정하지 않고 같은 심리 엔진(희소성+독점+되팔기)을 쓰는 대안(큐레이션 랜드마크판, 별자리/우주 소유권 claim판 등)도 병행 검토 중 — 확정되면 이어서 기록.

### 후속 업데이트 (2026-08-19, 같은 날 세션 내 13차에 걸친 상세 기획)

논의가 크게 진전돼 **기획서 초안이 사실상 완성**됐다. 전체 상세 내용은 [`drafts/지도-소유권-마켓플레이스-기획서.md`](drafts/지도-소유권-마켓플레이스-기획서.md) 참고(가격모델·게임화·소유권방식·출시범위·타겟유저 등 전 항목 확정, 개발 세션 핸드오프 가능 상태). 핵심만 요약:

- **가격모델**: 최초판매 $5 flat + 재판매 10% 수수료. 판매 인벤토리는 큐레이션 없이 전 지구 육지 균일 오픈(신뢰도 원칙), 매출 추정만 내부적으로 별도 분리.
- **소유권 방식**: NFT/블록체인 아님, 중앙DB 기록(개인자격·비가상자산사업 유지가 목적) — 단 ERC-2981 로열티 방식은 법률자문 전제로 재검토 후보 파킹.
- **정산 구조**: 에스크로 없이 매수자→매도자 직접 정산 + 수수료 자동공제(Stripe Connect/PayPal Commerce Platform류 업계표준). 결제는 PayPal 유력 후보(회장 최종검토 중).
- **게임화**: 경쟁형 리더보드는 최종 드롭 — 대신 필지 메시지·이름짓기·인접필지 조합배지·자유탐색 등 "이용 중 재미" 요소로 대체.
- **회사 독립적 가치**: 순수 디지털이라 구조적 한계 있음(인지만), 실물 기념패를 시즌2 확장 아이템으로 채택.
- **출시**: 테스트단계 5개국(한국·미국·중국·베트남·인도), 정식출시는 전 세계 동시 오픈. 예산상한 $1,000.
- **확장 로드맵**: 1순위 달·화성, 2순위 해저지형, 3순위 역사고지도(순서 132로 최종 조정, 최초안에서 2·3순위 순서 변경됨).
- **앱 이름**: **OwnEarth**로 최종 확정(2026-08-22, 출시 직전 상표·도메인 재검토 조건부). 도메인은 .com 미확보 상태 — 크로스플랫폼 서비스엔 .com이 필수가 아니라는 판단하에 .app을 1순위 대체 도메인으로 채택, .com은 서비스 성장 후 후순위 인수 옵션으로 정리.

### ① AI 언어학습 플랫폼 — 폐기 (2026-08-22)

타겟을 "한국어 배우는 외국인"으로 좁히고 타겟 국가(멕시코, 한류 팬덤·한국어 학습 성장세 데이터 근거)까지 좁혔으나, **회장이 "다들 같은 분석 하면 결국 같은 결론 아니냐"고 지적**했고 다온이 뒤늦게 직접 검증한 결과 실제로 그랬다 — Talkpal·koko·Sottaku 등 AI 대화형 한국어 튜터가 스페인어·인도네시아어·베트남어까지 이미 현지화돼 있고, 세종학당재단(정부기관) "AI 선생님"도 버전 2.0까지 나와있음을 확인. **국가·타겟을 아무리 좁혀도 "AI 대화형 한국어 학습"이라는 카테고리 자체가 이미 다국어·정부기관 경쟁자로 포화 상태**라는 게 뒤늦게 드러나 회장이 이 아이디어를 폐기 지시. 리서치 프로세스 자체의 실패(수요 근거만 먼저 보고 경쟁 확인을 뒤로 미룸)로 판단, 재발방지 원칙을 `README.md`("리서치 원칙 — 레드오션 체크가 아이디어 제시보다 먼저")에 구속력 있는 규칙으로 신설. 다음 아이디어부터 이 원칙 적용.

### ② "우리 운영구조를 귀여운 UI로 상품화" — 진행 중, 비주얼 톤(코지) 확정 (2026-08-22)

경로 2(내부에서 이미 하는 걸 상품화)로 탐색. 레드오션 체크 결과 "픽셀오피스로 AI 에이전트 시각화"(pixeloffice.org, pixel-agents, AgentOffice 등)와 "AI 에이전트 회사 템플릿"(`AI-company` 등) 둘 다 이미 존재하지만, 전부 **개발자 대상·코딩워크플로우 전용**이고 재무·의사결정로그·거버넌스 같은 "진짜 사업 운영" 요소나 저가 다운로드 과금은 아무도 안 하고 있음을 확인 — 비개발자 대상 + 사업운영 거버넌스 포함 + 소액 다운로드 과금이 남은 빈틈으로 판단.

회장이 이미 HQ 세션과 함께 만들어본 결과물(`nada-group/`, GlowHalo Group 오퍼레이션 콘솔)이 있어 다온이 직접 로컬 빌드해서 스크린샷으로 확인함 — 기능(회사·방·직원·승인/지시 구조)은 탄탄하나 **비주얼이 일반 B2B 어드민 대시보드에 가까워 매력도가 낮다**고 판단(캐릭터가 작고 밋밋함, "관계사 통합 현황" 섹션에서 게임 세계관이 완전히 깨짐, 라이트 테마 — 이건 "내부 운영툴 눈편함" 판단이었지 "상품 매력도" 판단이 아니었음).

**목업 1차(2026-08-22)**: 임시명 "Deskmates", 두 방향 스케치(도형 기반, 실제 에셋 없음) — **A. 코지**(따뜻한 우드톤, 큰 캐릭터, 러그·화분·액자) vs **B. 슬릭/쿨**(다크 터미널톤, 네온, 서버랙). "관계사 통합 현황"이 세계관 깨던 문제는 하단을 다른 회사로 이어지는 문 모양 포털로 바꿔 해결. **회장이 A(코지)를 선택.**

**다음 단계 — 실제 에셋 기반 비교(회장 요청, 나중에 진행)**: 톤은 코지로 정했지만, 실제 아트 에셋을 붙일 때는 화풍 자체를 다시 3갈래로 비교해보고 싶다고 명시:
1. 귀여운 픽셀아트
2. 게임 캐릭터 같은 고퀄리티 2D
3. 실사에 가까운 3D

**정정(2026-08-22)**: 톤(코지)이 세 화풍 전부에 적용된다고 다온이 잘못 이해했던 걸 회장이 바로잡음 — **픽셀아트만 코지로 확정**, 고퀄리티 2D·3D는 톤을 아직 안 정했고 새로 검토해야 함(예: 3D는 오히려 쿨/슬릭 쪽이 더 어울릴 수 있음). 화풍별로 톤을 독립적으로 판단할 것.

### 스코프 대전환 — "장난감"이 아니라 "실제 오케스트레이션" (2026-08-22)

앞서 다온이 제시한 갈림길("진짜 기능형" vs "장난감/커스터마이징형")에 회장이 명확히 답함:

- **타겟**: 클로드를 재밌게 잘 쓰고 싶은 **비개발자**.
- **기능**: **실제 오케스트레이션 + 시각화** — 사용자 본인의 클로드 계정과 연결해서 실제로 작동해야 함. 클로드 화면(claude.ai/Claude Code)에 직접 안 들어가고, **우리 앱 화면에서 지시를 주고받는 것**이 핵심 컨셉.
- **겉모습(UI 메타포)**: 비개발자에게 맞춰 쉽게 — "팀 생성" 버튼 = 세션 생성, "직원 고용" = 세션 내 에이전트 추가.

**다온 판단 — 여기서 즉시 확인해야 할 기술적 전제**: "본인 계정과 연결"이 (a) 사용자가 자기 Anthropic API 키를 입력하는 방식(BYOK, 표준적·안전)인지, (b) 사용자의 claude.ai/Claude Code 로그인 세션 자체를 자동화로 조작하는 방식(비공식적일 가능성, ToS 리스크)인지에 따라 완전히 다른 프로젝트가 됨 — UI를 더 다듬기 전에 이것부터 리서치하기로 함. 결과는 다음 항목에 이어서 기록.

### 연결 방식 확정 — "템플릿+뷰어" 아키텍처 (2026-08-25)

리서치 결과, (b)(로그인 세션 대신 조작)는 Anthropic 공식 정책상 명확히 금지("제3자가 claude.ai 로그인을 자사 제품에 제공하는 것 불허", 원클릭 연동용 OAuth 자체가 없음) — 우리 앱 안에 로그인창을 띄우는 것도 같은 이유로 불가능함을 확인. (a) BYOK는 가능하지만 타겟(비개발자)과 정면충돌(API 키 발급이라는 진입장벽) — 관리형(우리가 키를 대신 들고 프록시)은 원가구조가 완전히 바뀌어(사용량만큼 우리가 Anthropic에 지불) 애초 "다운로드 소액 정액"이라는 원가-거의-0원 가격구상과 안 맞음.

**최종 채택안 — 로그인도 API 연결도 아닌 "템플릿+비동기 파일 브릿지"**:
- 우리 앱은 API를 직접 호출하지 않는다. 대신 **"Claude Code에서 열기" 버튼**을 누르면 **claude.ai가 새 탭으로 열리고**, 거기서 사용자가 **본인 Pro/Max 구독으로 직접 로그인**해 우리가 준비한 템플릿(팀장·팀원 역할이 적힌 CLAUDE.md 등)을 그 세션에 로드한다. 로그인·세션 생성·실제 작업은 전부 그 탭 안, 우리 앱 밖에서 일어난다.
- claude.ai 세션은 작업하면서 프로젝트 저장소에 **상태파일**을 남긴다. 우리 앱(귀여운 컴패니언 뷰어)은 그 저장소를 주기적으로 **읽기만** 해서 픽셀오피스 화면으로 그려준다 — 클로드와 직접 통신하지 않는다.
- 사용자가 뷰어에서 새 지시를 입력하면 앱이 **지시사항.md**에 쓰고, 사용자가 다음에 claude.ai에서 그 프로젝트를 다시 열거나(또는 예약 실행 때) 클로드가 그 파일을 읽어 처리한다 — 이 저장소 자체의 `nada-group` 지시접수함(대시보드가 직접 LLM과 대화하지 않고 접수만 하면 클로드 세션이 비동기로 처리)과 동일한 원리.
- **부수 확인**: 이 방식(claude.ai 자체 화면·구독 그대로 사용)은 최근(2026-06-15) 생긴 "프로그래매틱 사용 전용 별도 크레딧" 과금 대상이 **아님**을 공식 도움말로 확인 — Agent SDK/API로 직접 붙이는 방식만 이 별도 크레딧 대상이고, 대화형 Claude Code 웹/Cowork/claude.ai 자체는 무관하다고 명시돼 있음. 즉 사용자는 원래 내던 구독료 안에서 그대로 쓸 수 있고, "완성품을 파는데 API 비용은 안 든다"는 원래 가격구상도 그대로 유지됨.
- 판매 형태도 이 구조 덕분에 둘로 나뉨: ① 설정파일/템플릿 팩(니치템플릿과 같은 카테고리, 검증된 판매방식) + ② 귀여운 컴패니언 뷰어 앱(AI 사용비용 0원, 다운로드 소액 유지).

**회장 확정(2026-08-25)**: 구조를 다이어그램으로 확인 요청 → 확인 완료, **"이 방식으로 하자"로 채택**. 다이어그램은 "이해됐고 잘 정리되어 있으니 나중에 설명서로도 넣자"는 평가와 함께 향후 온보딩/기술문서 자료로 재사용 예정(비동기 다이어그램: `/tmp` 세션 스크래치패드에서 Artifact로 발행됨 — 저장소에 정식 자산으로 옮겨 남기는 건 다음 단계 작업 중 하나).

**다음 단계 (미정, 다음 세션에서 다온과 상의)**: (1) 위 다이어그램을 저장소 내 정식 문서/자산으로 옮겨 보존, (2) ~~로그인 사용자 여정을 화면 흐름으로 구체화~~ → 완료, 아래 이어서 기록, (3) 확정된 비주얼 톤(코지, 위 항목)과 이 기술 구조를 결합한 실제 목업 다음 라운드.

### 사용자 여정 — 화면 흐름 S0~S7 확정 (2026-08-25)

리서치로 두 가지가 새로 밝혀짐:

1. **공식 프리필 딥링크 확인** — claude.ai/code는 `?prompt=&repositories=&environment=` 쿼리 파라미터로 새 세션의 프롬프트·저장소를 미리 채우는 공식 기능을 지원함([공식 문서](https://code.claude.com/docs/en/web-quickstart#pre-fill-sessions)). 이전에 "원클릭 연동 자체가 없다"고 판단했던 건 **로그인 연동**(OAuth로 인증을 넘겨받는 것) 얘기였고, **세션 내용을 미리 채우는 딥링크**는 별개로 존재했음 — 정정.
   - `claude-cli://` 딥링크(데스크톱 전용, OS 핸들러 필요)와 혼동 주의 — 우리가 쓸 건 웹 전용 `https://claude.ai/code?...` 쿼리 파라미터 방식.
2. **GitHub 계정이 이전 생각보다 훨씬 핵심적으로 필요함** — claude.ai/code 세션은 "연결된 GitHub 계정이 볼 수 있는 저장소"만 열 수 있음. 즉 "템플릿"은 추상적 개념이 아니라 **사용자 본인 GitHub 계정 안의 실제 저장소**여야 하고, 우리 템플릿을 그 계정으로 복사해두는 단계가 필수로 들어감 — 이 전제가 이전 논의엔 없었음.

**확정 화면 흐름**:

| # | 화면 | 내용 |
|---|---|---|
| S0 | 첫 실행 안내 | "클로드로 실제 작동" 설명 + 필요 조건(GitHub 계정·클로드 구독) 안내 |
| S1 | GitHub 연결 | 표준 GitHub OAuth, 우리 앱 밖 팝업 — claude.ai 로그인이 아니라 GitHub 로그인이라 정책 문제 없음 |
| S2 | 팀 만들기 | 저장소 이름 입력 → 우리 앱이 GitHub API로 템플릿을 사용자 계정에 자동 복사(generate-from-template) |
| S3 | 직원 고용(선택) | 역할 프리셋 체크 → 저장소 CLAUDE.md에 반영, 스킵 가능 |
| S4 | Claude Code에서 열기 | `claude.ai/code?repositories=<user>/<repo>&prompt=...` 새 탭 오픈. 최초 사용자는 claude.ai 자체 로그인+GitHub 연결이 한 번 더 뜸(claude.ai 쪽 1회성 절차, 우리 앱과 무관) |
| S5 | 뷰어 복귀 | GitHub API로 상태파일 주기적 폴링 → 픽셀오피스 렌더링, "마지막 갱신 n분 전" 표시로 비실시간임을 은연중 전달 |
| S6 | 지시 입력 | 뷰어 입력창 → 저장 시 우리 앱이 GitHub API로 지시사항.md 직접 커밋 |
| S7 | 재개 안내 | "다시 열어주세요" + S4 딥링크 재사용 버튼. **MVP는 예약 자동 재개 없이 수동 재개로 시작** — 자동화(Routines 활용)는 이후 과제로 명시적으로 미룸 |

**남은 마찰 포인트(정직하게 기록)**: S1~S2(GitHub 계정+템플릿 복사)가 비개발자 타겟에게 BYOK API 키 발급만큼은 아니어도 작은 진입장벽. 지금은 그대로 진행, 문제되면 재상의.

## 2026-08-22 — 파킹된 아이디어 (당장 논의 안 함, 나중에 이어감)

회장이 "기억해두었다가 나중에 얘기하자"고 명시적으로 요청. 지금은 평가·리서치 없이 원문만 보존.

1. **네이버 블로그 자동작성 + 네이버광고 결합** — 블로그 콘텐츠를 자동 생성해서 올리고, 거기에 네이버 광고(정확히 어떤 광고 상품인지는 미확정 — 네이버 블로그 애드포스트 등으로 추정, 확인 필요)를 붙여 수익화하는 아이디어.
2. **AI 병사가 숨어있는 P2P 오픈월드 전쟁 게임(더 넓게는 범용 컨셉)** — 처음 만난 AI가 잘 대해주면 우호적이 되어 싼값에도 용병으로 합류하고, 다른 플레이어가 돈을 더 주면 그쪽으로 가기도 하고, 의리 때문에 안 가는 AI도 있는 식으로 **AI들이 각자 성격·관계 이력을 갖고 인간처럼 반응**하는 구조. 전쟁 게임이 아니어도 되고, 핵심은 "플레이어와 수많은 AI가 뒤섞여 있고, 누가 AI고 누가 사람인지 구분하기 쉽지 않을 정도"인 가상세계를 만들어보고 싶다는 것.
3. **"계속 지켜보며 실시간 응대해야 성과가 좋은 분야"를 사람 대신 AI가 상시 대응** — 핵심 가설은 "24시간 붙어서 즉각 반응하는 게 성과를 좌우하는 분야"를 찾아서, 그 자리를 사람이 아니라 AI로 채우는 것. 회장이 든 예시: 주식·코인 투자(실시간 매매 판단), 빠른 서비스 응대, 즉시 답변, 챗봇. 아직 구체적인 분야·상품 형태는 미정 — 회장이 더 고민해보고 이어가기로 함. (참고: 실시간 코인/주식 매매는 이미 GlowHalo 3(은성, `asset-management/`)이 하고 있는 영역이라, 이 방향이 구체화되면 겹치는지 확인 필요 — biz-consulting/README.md의 "겹쳐도 매번 독립 검토" 원칙대로 문제 삼진 않되 인지는 해둘 것.)
