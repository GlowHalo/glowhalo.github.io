# 아기랑 갈곳 — 배포용 사본

`../baby-place-registry/`는 회장이 실제로 매일 쓰는 원본이라 손대지 않는다(2026-08-17 회장 지시). 이 폴더는
그 원본을 복사해서 스토어 배포용 개선(죽은 파일 정리, 하드코딩 주소 → 설정값 전환, PWA manifest/서비스워커/
아이콘 추가)을 적용한 사본이다.

- `meta.json`이 없다 — 루트 허브(`registry.js`)에 별도 카드로 뜨지 않도록 의도적으로 뺐다.
- Microsoft Store 제출(PWABuilder MSIX 패키징)은 이 폴더의 라이브 URL(`https://glowhalo.github.io/baby-place-registry-deploy/`)을 대상으로 진행한다.
- 원본에 적용할 만한 개선이 검증되면 그때 다시 원본에 병합할지 판단한다.

상세 변경 내역: `app-portfolio/candidates.md`, 커밋 `672ef16`.

## 상품 컨셉 (회장 확정, 2026-08-18)

이 앱은 "장소 추천/발견" 앱이 아니다. **"다른 데서(애기야가자·맘카페·인스타 등) 발견한 곳을,
마음에 들 때 저장해두는 지도형 메모장"**이다. 진짜 경쟁자는 네이버지도/구글지도의 "저장
리스트"(즐겨찾기) — 이름+색상 정도로만 구분되는 범용 북마크일 뿐, 육아 맥락에 맞는 구조화된
정보가 없다. 차별화 지점:

1. **캡처 속도** — 링크든 텍스트든 뭐든 붙여넣으면 바로 카드가 됨(네이버지도는 "장소 검색해서
   찾아야" 저장 가능, 이 앱은 몰라도 됨). 저장 자체는 아무것도 기다리지 않는다.
2. **육아 전용 구조화 필드** — 대상연령/실내외/만족도/메모, 그리고 사용자가 직접 늘릴 수 있는
   커스텀 구분값(기본 6종 + "+ 새 구분 추가").
3. **"진짜" 자동 분류** — URL 호스트명만 뽑던 수준을 넘어, `worker/`(Cloudflare Worker)가 링크를
   서버에서 대신 열어 `<title>`/`og:title`/`og:description`을 가져오고, 키워드 매칭(AI 호출 없음
   — 카페/커피→카페, 키즈카페/놀이터→실내·야외놀이, 맛집/식당→식당, 호텔/펜션→숙소 등)으로
   이름·구분값을 제안한다. 카드는 저장 즉시 생기고("분류중" 표시), 결과는 백그라운드에서 조용히
   갱신되며, 사용자가 언제든 수동으로 덮어쓸 수 있다(자동분류는 제안일 뿐 강제 아님).
4. **개인 육아 아카이브로서의 정체성** — 다른 사람에게 추천하기 위한 공개 목록이 아니라, 나와
   내 아이의 경험을 쌓아가는 기록.

`worker/`는 다른 앱들의 `worker/` 패턴(예: `mindmap/worker/`)을 그대로 따르는 별도 Cloudflare
Worker다 — 프론트엔드(GitHub Pages)에서 CORS 때문에 직접 못 여는 링크(인스타그램, 네이버지도 등)를
대신 fetch해서 메타태그만 돌려준다.
